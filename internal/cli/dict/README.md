# internal/cli/dict — 字典命令组

`tt dict` 的命令面。除了各查询命令，它还负责**每次调用打开与关闭查询数据源**——
那是这一组最要紧的机制。

## 数据源钩子

命令组的入口钩子做三件事：

1. **补跑祖先命令的钩子**。cobra 只运行"从叶命令往上找到的第一个"前置钩子 ——
   子命令一旦定义，父命令的就被整个跳过。这里显式往上找一遍，免得将来根命令加了全局初始化
   被静默漏掉。
2. **只在真的要用数据源时才打开它**。判据是"落到命令组自己身上"（没给子命令，或给了一个
   不认识的）—— 那两种情况没人要查库，而打开数据源在没配库的机器上会当场失败：
   于是 `tt dict` 想看一份命令列表，却拿到一句"本地数据库文件未找到"，
   `tt dict nope` 连"你打错了命令"都说不出来。
3. **把"这次落在哪"交给统一错误出口**：出错时"连的是哪个环境、哪个账号"比错误文本更难猜。

收尾钩子负责关闭数据源。**不依赖本地字典库的子命令覆盖这个钩子**（环境、镜像、库管理、
安装、服务、文档这类）。

## 参数

| 开关 | 说明 |
|---|---|
| `--db` / `-d` | 本地镜像路径（缺省 `erp_data.db`，也可用环境变量指定）；按"环境变量 → 绝对路径 → 相对 exe → 相对当前目录"解析 |
| `--limit` | **挂在命令组上，不是各命令上**：返回条数上限是全局策略。从前只有三个命令各自定义了一个，其余命令等于没有防线。缺省跟随配置，再缺省 20 |
| `--env` / `--conn` | 选数据源（环境名或 `local`）；**显式指定即强制** |

帮助末尾会附一行"本地数据齐不齐"（依赖哪个数据族、哪些表缺）—— 那与数据族定义同源。

## 命令一览

| 组 | 命令 |
|---|---|
| 表与字段 | `r.t`（表字典）、`r.v`（校验带值）、`desc`（字段画面规格） |
| 分类与开窗 | `scc`（系统分类码）、`r.q`（可复用开窗） |
| 程序 | `prog`（程序与作业、程序↔表格、子程序与元件） |
| 消息与参数 | `msg`、`sysp`、`docp` |
| 数据维护 | `db status` / `db sync` / `db list` / `db ping` / `db discover` |
| 源码与文档 | `mirror dir` / `mirror pull` / `mirror path`、`bdldoc dir` |
| 结果 | `spill list` / `spill show <文件\|latest>` |

## 结果太大怎么办

查询结果超出条数上限时，**完整结果先落盘、再截断**（落盘失败就不截），信封里同时给出
总量、返回量、落盘路径与"怎么看全量"。`spill list` / `spill show` 就是翻看那些落盘结果的入口
（`show` 支持翻页，所以信封里带一个偏移字段 —— "这是第 N–M 条"在信封里就有答案）。

## 判据

```bash
go test ./internal/cli/dict -count=1
```

覆盖：参数解析、落盘与翻页、环境与账号的解析降级路径。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 数据源钩子 | 所有查询命令的入口；钩子里的判据写错会让"打错命令"变成"数据库没找到" |
| `--limit` 的语义 | 全局策略，所有命令的输出规模 |
| 新增子命令 | 要么打开数据源、要么显式覆盖钩子（否则没配库的机器上用不了） |
| 帮助里的数据族提示 | 与数据族定义同源 |
