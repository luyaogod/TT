# internal/web — 统一本地服务的 HTTP 层

**一个进程、一个端口、一套页面。** 本包只做路由与静态承载，不含任何业务能力 ——
它把调试子系统与字典子系统的处理器接进来，页面统一由自己提供。

## 路由表

| 路径 | 内容 |
|---|---|
| `/api/health` | 健康检查（含版本） |
| `/api/hosts` GET / PUT | **环境与库配置的读写**（设置页的主入口） |
| `/api/dbprobe` / `/api/dbaccverify` / `/api/conntest` | 从服务器探测连接要素、验证账号、测试连接 |
| `/api/config/meta` / `/api/config/status` | 配置的元信息与**派生状态** |
| `/api/cache/clear` | 清缓存 |
| `/api/install` GET / POST / DELETE | 把 tt 加进 / 移出用户 PATH |
| `/api/shutdown` | 停止服务（仅在有停止回调时挂） |
| `/debug/api/*` | 调试子系统的接口（挂载时剥掉 `/debug` 前缀） |
| `/api/*` | 字典子系统的端点（源码镜像拉取、字典同步），**直接挂在共享层** |
| `/debug/` | 调试工作台单页应用 |
| `/` | 根路径 |

## 挂载决策：子系统只挂 API，页面归本层

**不把子系统的处理器整个挂在 `/debug/` 下** —— Go 的路由匹配到前缀之后**不再向外回落**，
子系统自带的兜底路由会把该前缀下所有请求吃掉，页面反而出不来。所以只把 `/*/api/` 转给子系统，
页面由本层从内嵌产物提供。

**字典子系统的端点挂在共享层而不是 `/dict/api/`**：那个前缀是为"字典页有自己的 SPA"存在的，
而那套页面已经并入统一设置页 —— 前缀不再有存在理由。包内注册的就是绝对路径，所以挂载时
不加剥前缀。**更具体的具名路由优先于 `/api/` 这条前缀模式**，两者不会互相遮挡。

## 配置端点的三件服务端兜底

`GET/PUT /api/hosts` 是设置页唯一的配置入口，服务端替它做三件事：

1. **校验归服务端**：空环境列表、重名、端口越界、库类型非法、活动环境指向不存在的环境 ——
   一律拒绝并给出中文说明，前端原样展示。
2. **保存时保留表单不管理的字段**（例如某环境的 SSH 隧道配置）：配置页没有对应的输入控件，
   按"整节替换"处理会把手工配的东西静默抹掉。代价是通过页面**删不掉**该字段 ——
   **宁可选"删不掉"**。
3. **写入成功后通知持有配置内存态的子系统重新加载**（接口由本包声明、调试子系统实现）。
   否则从别处改了环境，调试侧仍按旧环境连，表现是"改了没生效"。
   重新加载失败只记日志：配置已经落盘成功，不该把成功的写报成失败，但要让用户看见。

## 两个与静态承载有关的坑

- **目录请求不能交给文件服务器**：它对目录会返回一次到根路径的重定向，挂载前缀被丢掉，
  用户会从 `/debug/` 被弹到 `/`。目录一律直接给入口页。
- **未命中的路径要回落入口页**：刷新页面或直接粘深链接时，浏览器请求的是那个深链接本身，
  后端得回同一份 HTML 让前端路由接管，而不是 404。入口页本身带"不缓存"。

**派生状态单独一个端点**（`/api/config/status`）：它要判断配置里那些路径型取值是否真的存在，
而那需要摸磁盘；`/api/hosts` 是设置页每次进入都会读的热路径，把它们掺进去等于每次读配置都
摸一遍磁盘。它也放在统一层而不是子系统的私有接口里 —— 共用设置页不该被绑死在某个子系统上。

## 注入点

`Options` 就是注入面：前端产物、配置路径、版本、**两个子系统的处理器**、配置重载器、
停止回调、同步目标的缺省值。本包与调试子系统之间**没有任何 import 边**，耦合全在这里。

## 监听

地址为空时用配置里的监听地址，再空用缺省；**被占用时向后顺延**，返回实际使用的地址。
服务**不设写超时与空闲超时** —— 它要承载长连接与挂起的命令。

## 判据

```bash
go test ./internal/web -count=1
```

**覆盖**：路由与挂载、SPA 回落（深链接回落入口 HTML，而未知顶层路径由 `hRoot` 回 404）、
配置端点的校验与保留字段、派生状态；**三个"动作"端点的错误半边与其中一条快乐路径**
（`action_test.go`）。

**故意不覆盖**：`hDBProbe` / `hDBAccVerify` 的快乐路径（要真服务器，属 L4）；
`hConnTest` 是三条里**唯一能测全的** —— 它的下游 `erpdb.Open` 返回的是 `Connector`
**接口**，所以可以注入一个假实现走完 `Open → ServerVersion → Close`
（含"失败路径也要把连接关掉"这条）。

`Options` 上那三个函数字段（`ProbeDB` / `VerifyAcc` / `OpenDB`）就是为这个开的：
**nil = 用真实现**，所以生产路径的行为一字不差。它们与既有的 `Shutdown func()`
（"nil 表示不注册该端点"）是同一个惯例。

两种约定并存，读代码时别串：`dbprobe` / `dbaccverify` 失败回 **502**；
`conntest` 失败回 **200 + `{"ok":false,"stage":…}`** —— 后者是刻意的，
"连不上"正是这个端点要回答的问题，用 502 表达会让前端把"测试结果是连不上"
当成"请求本身失败了"。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 路由表 | 前端与所有控制端命令；**未知路径的兜底行为**（必须回 JSON，不能落 HTML） |
| 挂载方式 | 页面与接口的边界；改回"整个子系统挂前缀"会让页面出不来 |
| 配置端点的校验 | 设置页可保存的内容；放松校验会把坏配置写进文件 |
| `Options` 字段 | 接线处（统一服务的装配）；增减字段要同步改装配代码 |
| 端口顺延 | 用户看到的地址与控制端的自动寻址 |
