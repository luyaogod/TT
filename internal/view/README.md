# internal/view — 窗口与图像

**做什么**：按 pid 枚举顶层窗口、抓某个窗口的**真图**、裁掉不该有的东西、过一遍交付体检、
在图上画标注框（落点由调用方从协议里算出来，本层不猜坐标）。

**不做什么**：

- 不碰键鼠、不改窗口样式、不置顶（那是驱动层的事，本层不提供这些入口）；
- 不自己找"哪个是作业窗口" —— 窗口与作业的对应关系由上层（`tt fep` 的会话与 AUI）给出；
- 不做缩放：合成一律用 Go 的 `image/draw` 逐像素画。PowerShell/GDI+ 的 `DrawImage`
  会按 DPI 比自动缩放（96/120 → 画布右侧 20% 变黑），实测踩过。

## 抓图后端与理由（都在真机上量过）

| 后端 | 结论 |
|---|---|
| `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` | **首选**：不受遮挡、含标题栏与滚动条、不透出背后窗口的像素 |
| `GetDC(hwnd)` 客户区 | 降级：缺标题栏/滚动条 |
| `GetWindowDC` | **弹窗不能用**：会透出背后窗口的像素（实测看到过电子书网页） |
| 屏幕抓取 | 所见即所得，但**受遮挡**（实测抓到过两个窗口完全重合） |

漏掉 `PW_RENDERFULLCONTENT` 会得到一张全白图 —— 当年"QT 抓不了"的错误结论就是这么来的。

## 两条必须记住的规矩（各踩过一次）

1. **DPI 感知必须在任何 GDI 调用之前声明**。没声明时进程看的是虚拟桌面坐标
   （1920×1200 变成 1536×960），窗口右侧被剪 8~14px、左侧出现 7px 黑边 —— 而图看起来
   仍然"像一张正常的截图"。代码里用 `ensureDPI()`（`sync.Once`）保证顺序。
2. **枚举窗口只按 pid**（+可见+尺寸），绝不按类名：作业窗口与开窗的窗口类不同
   （`Qt5QWindowToolSaveBits` ≠ `Qt5QWindowIcon`），按类名过滤会漏掉开窗。
   枚举是同步跨进程调用，所以带超时（`ListTimeout`）：目标线程忙时不能让命令一起卡住。

## 阴影裁切

DWM 给窗口留的阴影区在 PrintWindow 里是**纯黑**（实测左/右/下各 9px，窗口矩形外扩 -9,-9）。
裁切的坑：**左右列的检测必须跳过标题栏那几行**（标题栏是亮的 243,243,243），否则标题栏
会让整列判成"非黑"，一列都裁不掉。

## 交付体检（`Check`）

抓图是"看起来对"最容易骗人的一步。每次抓完自动过：

1. 几乎只有一两种颜色 → 全白/全空图（多半漏了 `PW_RENDERFULLCONTENT`）；
2. 右端出现纯黑列 → 没裁阴影，或抓图区域被剪（DPI 感知没声明）；
3. 尺寸异常。

体检不过：`tt view shot` 退 **4**，并把问题打出来。

## 判据

- `go test ./internal/view/`：阴影裁切（含"标题栏行不参与左右判定"）、无黑边时不乱裁、
  体检能指出全白图与黑列、窗口筛选与按名查找；
- 真机：`tt view shot --pid <pid>` 抓一个真实窗口 → 图片尺寸 = 窗口矩形减两侧阴影、
  颜色数正常、体检零问题（实测：1938×1158 的窗口 → 1920×1140，363 色）。

## 协议坐标 → 图像坐标（`annotate.go`）：机制已就位，一个测量待真机

`Derive` 从**参照物**推出比例与偏移（不写死比例：换主题/换机器就全错，而且错得很像对的），
推出来的东西离谱就**报错**；`RegionVerdict` / `GateFields` 是像素级可见性门
（计划 §2.12）：说明里点名的栏位必须在那一帧里真的画出来了。

**离线卡在一个测量上**（不猜，留真机）：真实 AUI 的几何属性**单位不统一** ——
实测同一屏里 `ButtonEdit 272 {width "8"} {posY "2"}`（**字符格**）与
`Window 178 {width "1912"}`（**像素**）并存。所以"哪个对象是客户区、哪个坐标系对哪个"，
离线推不出来：拿窗口当参照物会推出荒唐的纵向下移（实测 1038px），拿并集也被像素对象带偏。

因此当前行为是**拒画**：`tt view marks` 在映射推不出来时退 **4** 并说明理由，
绝不画一个"看着像"的框。下一次真机联调要做的测量：抓一帧 GDC、把已知栏位
（如「客户编号」）的框叠上去，用眼睛确认落点 —— 那一步会定下单位与客户区上沿，
之后映射才有依据。
