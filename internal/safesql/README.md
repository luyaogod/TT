# internal/safesql — 只读 SQL 的文本层防线

判断"一条语句看起来像不像只读"。用在命令行的只读查询入口上。

## 它是防线之一，不是全部

**别把它当成"过了就绝对安全"。** 真正兜底的是另外两层：

| 层 | 谁负责 |
|---|---|
| 本项目这一层 | 只读语句的文本白名单（本包） |
| 值不拼进命令行 | [../host/README.md](../host/README.md) 的标准输入通道 |
| 库侧只读事务 | 数据库自己（连上去之后设只读事务） |

## 它原则上看不出来的两件事

如实写在这里，不粉饰：

1. **自治事务**：一个看着是 `SELECT` 的函数调用，内部可以真的写库并提交 —— 只读事务也拦不住它。
2. **工作量**：限制返回行数不等于限制扫描量。

**它是文本扫描，不是 SQL 解析器。**

## 判据

```bash
go test ./internal/safesql -count=1
```

覆盖：白名单的接受与拒绝面（多语句、写操作、注释绕过等）。
