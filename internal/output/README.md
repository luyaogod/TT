# internal/output — 唯一的输出出口

所有查询命令的输出都从这里走。三种形态、一个入口：

| 形态 | 内容 |
|---|---|
| **JSON 信封**（缺省） | `{ok, source, env, …, data}` —— 机器读 |
| CSV | `# ` 注释头 + 裸 CSV 主体 —— 管道友好 |
| 人读表格 | 对齐表格 —— 给人看 |

缺省是 JSON，依据是表格类格式对模型的理解力实测更低，而 JSON 又省掉解析歧义。

## 为什么信封里要回显这么多

**同一个企业编号在开发区与正式区是两套完全不同的库，同一个环境里不同账号又是不同的 schema。**
少回显一半，就可能把"查错了地方"读成"数据不存在"。所以 `Meta` 把"这次落在哪"整条链都记下来：

| 组 | 字段 |
|---|---|
| 出处 | 数据源（本地/在线）、环境、SSH、区域、环境配的企业编号、**本次实际用的企业编号**、账号、**账号来源**、库目标、方言、路由、是否走隧道、是否只读事务、本地库路径 |
| 计数与截断 | 总行数、返回数、翻页偏移、是否截断、截断原因、是否"库侧就已限流" |
| 落盘与杂项 | 落盘文件路径、落盘是否不完整、耗时、备注 |

**字段全可空，空的整段不打印** —— 本地源拿不到 SSH，就不出现 `环境 · SSH · 区域` 这种
一个值都没有的空壳行。

## 四条不许破

1. **空段不打印**（上表）。
2. **企业编号与账号同在一行**，写成一条链：`企业(ENT) 99 → 账号 dsdemo` —— 拆成两行会被读成
   两件可以各自独立看的事。
3. **截断绝不静默，结果绝不丢**：截断行会把"总共多少、回了多少、完整在哪、怎么拿全量"一次讲清；
   库侧限流时把总数写成"库侧返回 ≥ N"（那只是下界，说成"共 N 条"会让人以为就这么多）。
   **0 行时必须点名**"上错号 / 上错环境也会是 0 行" —— 那是本工具最容易误读的一种结果。
4. **stdout 只放数据**（JSON 模式）：诊断进备注或 stderr。CSV 的 `# ` 注释头留在 stdout
   是**刻意例外** —— 头必须随数据走，管道里没法把 stderr 与 stdout 重新配对。

## 错误：稳定码 + 退出码

错误也是信封（`ok:false` + 码 + 消息 + 提示 + 退出码），**码是对外契约**：
消费方靠码分支、人读消息。**加新码可以，改旧码的名字不行。**

| 码 | 含义 |
|---|---|
| `USAGE` | 用法 / 参数错 |
| `ENUM_INVALID` | 枚举取值非法 |
| `ENV_UNKNOWN` | 环境名不存在 |
| `CONFIG_BROKEN` | 配置缺失或坏了 |
| `TABLE_MISSING` | 字典表不在库里（该数据族未同步） |
| `CONNECT_FAILED` | 连不上库 / 服务器 |
| `SQL_REJECTED` | 语句没过白名单 |
| `QUERY_FAILED` | 查询本身失败 |
| `NOT_FOUND` | 查到了，但没有这条数据 |

退出码：`0` 成功（含"查无结果"）/ `1` 用法或参数校验错 / `2` 数据源错（连不上、配置坏）/
`3` 缺表。**0 与 1 沿用 tt 既有语义，只新增分类码** —— 重新编号会把既有脚本的判据改掉，
而换来的只是对齐一个没有权威性的约定。

## 入口

| 入口 | 用途 |
|---|---|
| `Emit(w, Options)` | 唯一的输出出口（按形态分派） |
| `WriteJSON` / `WriteCSV` / `WriteMeta` | 分形态的低层写入（可注入 writer，便于单测） |
| `Meta.headerLines` / `countLine` | 信封与 CSV 注释头的渲染规则 |
| `Error` / `Errorf` / `WithHint` | 带稳定码与退出码的错误 |

## 判据

```bash
go test ./internal/output -count=1
```

覆盖：三种形态的渲染、空段不打印、企业编号与账号同行、截断与 0 行的文案、错误信封的形状。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| `Meta` 增删字段 | 对外信封的形状；加字段要带 `omitempty`（既有命令的输出一个字节不变） |
| 错误码的名字 | **冻结契约**，改名等于破坏消费方 |
| 退出码 | 所有脚本的一次性判据 |
| 表头渲染规则 | CSV 的注释头与 JSON 的信封必须同源 —— 两处写法不一致就会出现"同一件事两个说法" |
| 换掉/新增渲染器 | **这条线只允许一个出口**：多套渲染器的字段与格式必然各写各的，而它们描述的是同一件事 |
