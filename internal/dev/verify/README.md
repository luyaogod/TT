# internal/dev/verify — 三道闸门

写回之前的**机械证明**：改了的是不是只有该改的那些，产出的包设计器打不打得开。

| 闸门 | 检查 | 失败 |
|---|---|---|
| **gate1** | 字节恒等 + 写入授权 | 校验失败；权限类 → 4 |
| **gate2** | 不变量全集 I1–I15 | 校验失败 |
| **gate3** | 对**将要产出的新包**重跑合成 = "设计器打得开吗" | 校验失败 |

管线顺序即契约（取自 `cli.go` 的 `cmdApply`）：
`解析围栏 → gate1 → 源包未变校验 → 回写拆分 → gate2 → 改写字节 → gate3 → 原子写 → 提交`。
gate3 在写之前、对内存里的新包执行。**任何一步失败，原包字节不变。**

## gate1：判定面 = 全文 − 可写区间

这是本包最要紧的一条设计。gate1 不逐条列举"哪些地方不许改"，而是先算出**可写字节区间**，
然后比对**其余全部字节**：

```
可写区间 = 自订定义点的正文本体（函数头 / 注释头 / END 行都在其外）
         + 裸名插入点的整块内容
         + 已解锁区段的正文
```

于是围栏行、未归属字节段、只读区内容、可编辑区里的**结构行**全都被物理保护 ——
新增一个"可编辑的地方"必须显式扩大这个集合，不会因为某处漏判而失守。

比对时对**受保护字节**按**行尾等价**处理：编辑器把 CRLF 归一成 LF 不算改动（那类字节本来就
从不写回包）。这类情况给一条 `gate1.eol-normalized` 的 **info**，让人知道发生过什么。
可编辑区里除了行尾归一之外还有实质改动的，才按"你文档里的行尾"重写。

## gate2：不变量 I1–I15

对**编辑后将写回的 TAP** 与编辑后的文档做一致性判定：

| 码 | 内容 | 等级 |
|---|---|---|
| `I1` | 区段配对标定、id 唯一、与 TAP 的 `<section id>` 对应 | error（个别分支 warn） |
| `I2a` | TGL 有占位符而 TAP 无对应点 → **造空点**，是常态 | **info** |
| `I2b` | TAP 有自订点而 TGL 无锚点 → 代码彻底不出现 | error |
| `I2c` | TAP 裸插入点无同名占位符（孤儿点）→ 必须原样透传 | warn |
| `I3` | 区段正文里混进了完整函数块 | error |
| `I4` | 自订点的定义头形态（先剥修饰符再匹配） | warn |
| `I5` | 状态取值合法；删点要保留原内容 | error（个别分支 warn） |
| `I10` | `.4gl` 与"框架 + 展开点"本来就不一致 | **info**（提醒别试图同步） |
| `I11` / `I11b` | 编码与 CDATA 合法性（无 BOM、无控制字符、新内容里无 CDATA 结束序列） | error |
| `I13` | 未知条目与版本文件字节原样 | error |
| `I-structure` | 可编辑点的**结构行**未改 | error |

`gate2` 的输入是"将要写回的那份 TAP"：`apply` 时是新 TAP，`verify` 时是原 TAP。

## gate3：装载模拟

对将要产出的新包字节重跑一遍合成（"设计器打得开吗"）。它**不碰用户的原包** ——
只写到临时文件再读回。失败时按步报码：`gate3.open` / `gate3.synthesize` / `gate3.render` /
`gate3.fence` / `gate3.tap` / `gate3.build` / `gate3.invariants`。

自动化只到这一步为止；真正的验收是在装了设计器的机器上打开产物（见
[../README.md](../README.md)）。

## 发现、等级与退出码

一条发现是 `Finding`：码 + 等级 + 位置（文件、1-based 行号、该行内容）+ 可选明细。
等级三档 `info` / `warn` / `error`；**退出码由发现决定**：

```
只要有 error 级且标记为"写入被拒"的发现 → 4
否则有 error 级 → 3
```

`info` 与 `warn` 默认不失败；`verify --strict` 把 warn 也算作失败（供 CI 用）。

## 结构事务 V1–V7

改名 / 改 scope / 改描述这类"点的身份变了"的操作要跨多处保持一致，所以单独一套校验：

| 码 | 判定 | 等级 |
|---|---|---|
| V1 | 围栏里的 `fn` 与签名行的函数名一致 | error |
| V2 | 旧名残留引用清零：可编辑区里由你自己改；**只读区段里改不了 → 写入被拒（4）** | error |
| V3 | 新名不与现存的点/占位符重名（含本次会话内的冲突与交换式改名） | error |
| V4 | 命名规范（前缀）——与设计器一致，只提示 | warn |
| V5 | scope 与程序类型的默认关系 | warn |
| V6 | 描述块里非空行必须以 `#` 开头（**空行合法**）；等级按"是否本次改动过"区分 | error / warn |
| V7 | 目标必须是可编辑的自订定义点 | error |

它放在 `verify` 里而不是独立包，是因为要返回 `Finding`，独立包会造成循环依赖。

## 判据

各条**拒绝路径**由端到端用例覆盖，而且它们**已经在默认档里跑** ——
`tt dev tzc selftest` 的 31 项被接进了 `go test`（见根 `TEST.md`）。
所以本包的单测不重测那些，补的是端到端钉不到的两件：

```bash
go test ./internal/dev/verify -count=1
```

**覆盖**：
- **干净路径零误报** —— 原样渲染、原样解析的文档不该有任何 error。端到端只会在
  "该拒绝的没拒绝"时红，而"不该拒绝的拒绝了"在它那边是一片对不上的失败，
  定位不到是哪个闸门误报。
- **gate1 的行尾等价那条设计决定**：受保护字节的 CRLF↔LF 归一算 **info 不算 error**
  （不然编辑器一次"另存为"整份文档全红，真问题会淹在里面）；而等价**有边界** ——
  只读区正文里真的动了内容照样拦下，且带 `Denied` 标记（退出码 4 而不是 3）。
- `Report` 的计数与摘要：**`Denied` 是 `Errors` 的子集**（一条被拒的发现同时计入两栏），
  且只认 error 级。

**故意不覆盖**：gate3 的装载模拟（要真包与真字节）—— 那由 `tt dev tzc selftest` 的
apply 用例负责。**它验不了"设计器会不会拒绝这个容器"**，那要靠真机验收。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 新增一条不变量 | 要想清楚三件事：给什么等级、是不是"写入被拒"（决定退出码 3 还是 4）、以及它在 `verify` 与 `apply` 两侧是否都该跑（两条路径共用本包的闸门） |
| gate1 的可写区间 | 与 [fence](../fence/README.md) 的 Region 语义耦合；这里是"不破坏"的最终防线，放宽等于放走误写 |
| 新增发现码 | 码是**对外文本**（`--json` 里出现、报错里出现），改名等于改契约 |
| gate3 的步骤 | 它是"设计器打得开吗"的最后一道自动化判决；**它验不了"设计器会不会拒绝这个容器"**，那要靠真机验收 |

改动之后至少要跑：

```bash
go test ./internal/dev/verify -count=1      # 本包单测（干净路径 + 行尾等价 + Report 计数）
./tt.exe dev tzc selftest                   # 对抗用例（改只读区、删围栏、塞非法字符…）
TDEV_DEEP=1 go test ./internal/dev/cli -run TestCorpusExportVerify
                                            # 全语料验证（9–11 分钟）
```
