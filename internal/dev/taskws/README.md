# dev/taskws —— 任务工作区

一个程序、一个任务、一个自包含目录。`tt dev open` 建它，`tt dev <动词>` 用它，
`tt dev apply` 产出要交给设计器的包。

## 为什么要有它

材料目录（`devdata/<环境>/prog/<程序>/`）回答的是"这个程序的材料在哪"。一次开发要的
是"这个**任务**的全部输入与输出"：材料、索引、可编辑视图、要交出去的包、变更记录。
把它们放在一棵树里，才谈得上断网可干活、可回放、可交接。

它同时把"地址"从环境换成了目录：读命令（status/brief/find/at/search）不再需要
`--at`，也不需要配置文件 —— 只读工作区里的三份文件。

## 目录

```
<工作区>/
├─ task.json          身份 + 历史（不含实时状态）
├─ materials/         材料（devdata fetch 的落点，含 manifest.json 指纹）
├─ mdl/slice/         模板切片（可选，切片脱版检测用）
├─ index/link.json    蓝图 ↔ 代码 索引
├─ ws/                tzc 围栏工作区（唯一编辑文件 ws/prog.full.4gl）
├─ pkg/<程序>(c).tzc  交给设计器的产物
└─ notes/             人的备注（工具不碰）
```

实测体积（axmt500_wf，9 个材料文件）：材料 11.8 MB、索引 0.9 MB、视图 3.9 MB、
包 0.96 MB —— 一个工作区约 17 MB。

## 三条纪律

1. **task.json 只存身份与历史**，不存"是否脏""包 sha"这类会变的量。
   存了就会与 `ws/manifest.json`、包的实际内容打架，而打架时错的总是"看起来新"的那个。
   所有实时状态由 `GetStatus` 现算（读几份小文件 + 包 sha，几十毫秒）。
2. **有未落盘改动时拒绝 update**。材料换了视图没换，行号会静默错 —— 这类错没有报错可循。
   出路写在错误里：先 `apply`/`verify`，或 `--force` 只刷材料（不动视图与包）。
3. **模板树放在 materials 外面**。`fetch --force` 是整目录原子替换，放里面会被连带清掉。

## update 的三种情形

| 现状 | 行为 |
|---|---|
| 视图干净、包没 apply 过 | 重拉材料 → 重建索引 → 重新打包 → 重新导出视图（整体对齐） |
| 视图有未落盘改动 | **拒绝**（`ErrDirtyWorkspace`）；`--force` 时只更新材料与索引 |
| 包里已有 apply 过的成果 | 只更新材料与索引；包与视图原样保留（成果不能冲掉） |

`--check` 只向服务器核对（mtime/大小），一个字节都不写 —— 视图有未落盘改动时也能用（那正是最想知道"服务器有没有新规格"的时刻）。

## 包"有没有改动"怎么判

判据是**包里的 .tap/.tgl 与材料不同**（逐字节），不是"包 sha 变了"。

原因：apply 成功之后 tzc 会把工作区基线一起更新，包 sha 与基线 sha 又相等了 ——
拿 sha 比对会把刚做完的活判成"没动过"（实测踩过）。材料缺件时才退回 sha 比对。

## 包路径必须绑在"当前工作区"

`ws/manifest.json` 里 `pkg.path` 是**绝对路径**，apply 默认照它写回。工作区一旦被复制/移动/
发给同事，清单还指着原目录 —— 一次 apply 就会静默写进别人的包，而 `status` 还会说"可交付"。

所以 `tt dev apply` 在动手前先 `RebindPackage`：把路径绑回本地，并要求本地包的 sha256 与
视图基线一致；不一致就拒绝（`ErrPackageMismatch`），提示放回基线包（`ws/.tdev/prev.tzc`
是上一步备份）或 `update --full` 重建。`status` 里有对应的 `pkg.matchesBase` 与提示。

## 包被换过：relink

apply 的"源包未变"校验在包被替换后会永久失败。`Relink` 以当前包为新基线重导视图
（脏工作区默认拒绝），把工作区从死局里拉回来。`status` 的 `pkg.matchesBase` 就是这条
校验的状态；不一致时摘要行不会再写"可交付"。

## 与另外两条线的分工

| 命令 | 地址 | 联网 |
|---|---|---|
| `tt gen …` | `devdata/<环境>/` | fetch/status 可选；map/查询离线 |
| `tt dev tzc …` | 某个 `.tzc` 或工作区目录 | 离线 |
| `tt dev <动词>` | 任务工作区目录 | 只有 open/update 要联网 |

工作区的视图就是 tzc 工作区，`tt dev apply/verify/unlock` 直接转给 tzc 的动词
（`ExitCode` 与输出契约完全一致），没有第二套写包实现。
