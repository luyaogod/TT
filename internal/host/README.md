# internal/host — 远程服务器能力层

**唯一的 SSH / 远程服务器层**：环境模型、连接、登录后动态取环境、源码镜像、服务器侧只读探测。
调试线与字典线都建在它上面。

**它不维护跨进程状态**：tt 除服务外都是一次性命令，探测结果只在单进程内用。

## 一条连接，多类通道

一条 SSH 连接上开多个通道：**PTY**（登录 shell 交互）、**SFTP**（传文件）、**exec**（跑命令）。
几条与安全有关的做法：

- **SQL 一律走 stdin**，不拼进命令行（拼进去等于把值暴露在远端进程表里，也给注入留了门）。
- 数据库账号与口令走**环境变量或标准输入**，不进命令行历史。
- 工具路径、账号名一类要拼进远端命令的值，过白名单校验。

## 环境模型只定义一次

环境的类型（SSH 要素、企业编号、库要素、账号清单）**定义在配置文件那一层**，
本包以**类型别名**暴露 —— 所以两个包里的同名类型是同一个类型，调用方无需转换，
也不会出现两份定义各自漂移。

## 登录之后才知道路径

T100 **没有** `$TOPDIR` 这种固定根：登录区域经站点配置得到区域目录名，其余路径全部由它派生。
所以**路径类取值不允许静态配置** —— 登录后动态取回是唯一权威来源，取不到就报错，不猜。

回读的变量由一段**带定界符**的探针脚本产出。定界符不是洁癖：登录脚本自身也会打印同名变量行，
而 PTY 只有纯文本、没有区间 —— 不定界就分不清"我们请求的回显"与"服务器自己说的话"。

**区域码是拼进远端 shell 的字符串**，必须过白名单（历史教训：它曾被裸插，于是
`--zone "36; id"` 能在服务器上执行任意命令）。

## 源码镜像

把某环境的文件拉到本地镜像目录。**一个环境只有一个镜像目录，而本地命令各自只认其中一类**
（`tt outline` → 4gl；`tt interface` → 42f/42s），所以默认的 `source` profile 必须收全：

| profile | 收什么 |
|---|---|
| `source`（默认） | `4gl/**/*.4gl` + `42f` + `42s/zh_CN` + `*.inc` |
| `interface` | 只 `42f` + `42s/zh_CN`（想只要画面时配一个独立目录） |

`.4gl.src`、`.4gltest`、`.str`、`per`、其它语言目录、备份都不收；4fd 是设计期字段描述，
fieldId 不稳定，两个 profile 都不收。`*.inc` 没有任何命令直接读，它服务的是“人/AI 离线读码”
（全局变量、共用参数）—— 缺了同样不报错，这类静默缺口最该避免。其它语言、设计器辅助一概不拉；
本地目录与服务器同构。

实现是"服务器侧打包 → 流式下载 → 本地解压"，全程不进内存。**两种拉取方式，服务器侧都不留状态文件**：

| 方式 | 服务器侧做什么 | 本地做什么 |
|---|---|---|
| 增量（默认，有基线时） | `find -newermt <基准>` 只打包比基准新的文件 | 按文件原子替换（同卷临时名 + rename），不碰其它文件 |
| 全量（`--full`） | 重压全部白名单文件 | 整目录替换（服务器上已删的本地也消失） |

**增量不写服务器状态，基准存在本地**：`.tdict-mirror.ok` 里记着上次拉取时**服务器**给的
时间戳（打包脚本在 `find` **之前** `date -u` 取一次，随 `TDICT_MIRROR_STAMP` 标记回传）。
旧实现是在 `$TOP` 放 marker 并在 `tar` **之后**才 `touch` 它 —— tar 运行期间改动的文件
下一次 `-newer` 就永远抓不到。现在基准在打包开始前就定死，漏文件那个竞态从根上没有了。

增量感知不到"服务器上删了文件"（那需要服务器侧全量比对），所以想让本地与服务器完全一致、
或镜像已经乱了，走 `--full`。没有本地基线（首次、标记版本不符、没拉过这个 profile）时
无论如何都是全量 —— 前端那个「增量更新」按钮在无基线时是禁用的，免得名不副实。

归档先落在**服务器临时目录**（默认 `${TMPDIR:-/tmp}`，可用 `mirror.tmpDir` 覆盖），
下载完立即删除。清理分四层：打包脚本自己删清单/半截归档、客户端 `defer` 无条件删
（成功/失败/取消都走）、取消时关掉 session 让远端 `tar` 立刻退出、客户端被强杀时
靠下一次拉取的 3 小时清扫兜底。`$TOP` 一个字节都不写，所以**不要求登录账号对 ERP
顶级目录有写权限**（旧版本写在 `$TOP`，这是个真实的部署障碍）。

两种方式都只对本 profile 的白名单负责 —— 不属于它的既有文件原样保留（不因“给一类做全量”
而删掉另一类）。备份/临时文件不拉，并会清掉本地残留。

**从旧版本升级**：`.tdict-mirror-*` 这套服务器侧标记文件再也不被读写，会一直躺在 `$TOP` 里，
需要手工清一次：`rm -f "$TOP"/.tdict-mirror-*`。不清也不影响功能。

## 服务器侧只读探测

登录服务器自动获取数据库连接要素，以及用显式账号口令连库验证。它**只读**：不建库、不改配置。

## 与客户端直连的分工

| | 服务器侧（本包） | 客户端直连（[../dict/live](../dict/live/README.md) + [../erpdb](../erpdb/README.md)） |
|---|---|---|
| 服务谁 | `tt debug` 的库相关命令 —— 它要在**那台服务器**上跑 SQL | 所有字典查询与库同步 |
| 隧道（`viaSsh`） | **无意义**（本来就连着服务器），静默忽略是正确的 | 只在客户端到不了库时才配 |

两边**不互相搬能力**：不为了"统一"把字典查询改走 SSH（一次直连查询会变成多次往返，
还把库的可见性绑死在服务器上），也不给服务器侧加隧道支持。

## 判据

```bash
go test ./internal/host -count=1
```

覆盖：环境变量探针的解析与定界符、连接与输出通道、镜像两个 profile 的白名单、
两种拉取方式的打包脚本（全量无 `-newer`、增量有 `-newermt` 且都不 `touch` 服务器状态）、
增量解压只覆盖归档内文件、基准时间戳往返、临时目录清理（空间预检、3 小时清扫、本地 staging 残留）。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 探针脚本 / 定界符 | 所有依赖登录后环境的命令（调试、字典的服务器侧路径） |
| 白名单 | 远端命令注入面；放宽一条就等于开一个口子 |
| 镜像的收取范围 | 本地镜像的内容与 AI 读到的代码；**收紧会让模型看不到某类文件，而它不会报错**；`interface` profile 必须保留 42f/42s |
| 临时目录 / 清理规则 | 服务器上会不会留垃圾；少一条 `rm`、少一次 defer 都要靠真机才看得出来 |
| 连接层（通道模型） | 调试与字典两条线都依赖 |
