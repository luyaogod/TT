# internal/host — 远程服务器能力层

**唯一的 SSH / 远程服务器层**：环境模型、连接、登录后动态取环境、源码镜像、服务器侧只读探测。
调试线与字典线都建在它上面。

**它不维护跨进程状态**：tt 除服务外都是一次性命令，探测结果只在单进程内用。

## 一条连接，多类通道

一条 SSH 连接上开多个通道：**PTY**（登录 shell 交互）、**SFTP**（传文件）、**exec**（跑命令）。
几条与安全有关的做法：

- **SQL 一律走 stdin**，不拼进命令行（拼进去等于把值暴露在远端进程表里，也给注入留了门）。
- 数据库账号与口令走**环境变量或标准输入**，不进命令行历史。
- 工具路径、账号名一类要拼进远端命令的值，过白名单校验。

## 环境模型只定义一次

环境的类型（SSH 要素、企业编号、库要素、账号清单）**定义在配置文件那一层**，
本包以**类型别名**暴露 —— 所以两个包里的同名类型是同一个类型，调用方无需转换，
也不会出现两份定义各自漂移。

## 登录之后才知道路径

T100 **没有** `$TOPDIR` 这种固定根：登录区域经站点配置得到区域目录名，其余路径全部由它派生。
所以**路径类取值不允许静态配置** —— 登录后动态取回是唯一权威来源，取不到就报错，不猜。

回读的变量由一段**带定界符**的探针脚本产出。定界符不是洁癖：登录脚本自身也会打印同名变量行，
而 PTY 只有纯文本、没有区间 —— 不定界就分不清"我们请求的回显"与"服务器自己说的话"。

**区域码是拼进远端 shell 的字符串**，必须过白名单（历史教训：它曾被裸插，于是
`--zone "36; id"` 能在服务器上执行任意命令）。

## 源码镜像

把某环境的源码拉到本地镜像目录，**只收这四类**：4GL 源码、前端字段描述、编译字符串
（只取简体中文目录）、4GL 包含文件。界面源码、其它语言、设计器辅助一概不拉 ——
AI 读的只是源代码与中文字符串，本地目录与服务器同构。

实现是"服务器侧打包 → 流式下载 → 本地解压"，全程不进内存。增量靠服务器上一个标记文件
（默认只打包比它新的文件）；**白名单升级时本地基线版本不一致，自动转全量补齐**，
否则新增的文件类型永远不会出现在镜像里。备份/临时文件不拉，并会清掉本地残留。

## 服务器侧只读探测

登录服务器自动获取数据库连接要素，以及用显式账号口令连库验证。它**只读**：不建库、不改配置。

## 与客户端直连的分工

| | 服务器侧（本包） | 客户端直连（[../dict/live](../dict/live/README.md) + [../erpdb](../erpdb/README.md)） |
|---|---|---|
| 服务谁 | `tt debug` 的库相关命令 —— 它要在**那台服务器**上跑 SQL | 所有字典查询与库同步 |
| 隧道（`viaSsh`） | **无意义**（本来就连着服务器），静默忽略是正确的 | 只在客户端到不了库时才配 |

两边**不互相搬能力**：不为了"统一"把字典查询改走 SSH（一次直连查询会变成多次往返，
还把库的可见性绑死在服务器上），也不给服务器侧加隧道支持。

## 判据

```bash
go test ./internal/host -count=1
```

覆盖：环境变量探针的解析与定界符、连接与输出通道、镜像的排除集与增量标记、探测的白名单。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 探针脚本 / 定界符 | 所有依赖登录后环境的命令（调试、字典的服务器侧路径） |
| 白名单 | 远端命令注入面；放宽一条就等于开一个口子 |
| 镜像的收取范围 | 本地镜像的内容与 AI 读到的代码；**收紧会让模型看不到某类文件，而它不会报错** |
| 增量标记格式 | 已有镜像的基线；格式变了要能自动转全量（否则镜像悄悄过期） |
| 连接层（通道模型） | 调试与字典两条线都依赖 |
