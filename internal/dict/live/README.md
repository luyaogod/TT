# internal/dict/live — 远程直查

直连客户的 ERP 库执行字典查询。实现 [../db](../db/README.md) 的 `Source` 接口，
**与本地镜像同语义** —— 同一套字典表、同一批 JOIN、同一批返回结构，只是数据是现查的。

## 两条实现约束

**一、没有绑定参数。** 连接器走的是简单协议，不支持参数占位，所以**所有值经白名单与引号
处理后内联**（标识符白名单 + 字面量引号）。这是本包唯一的注入面，每一处内联都必须过它。
结果仍然是单条只读查询。

**二、隧道是可选的一层。** 客户端到不了库、但库对 SSH 服务器可达时，先起一条端口转发，
连接目标换成本地回环地址 —— 驱动层不需要知道隧道存在（见 [../../sshtun/README.md](../../sshtun/README.md)）。

## 方言

金仓与 Oracle 双方言集中在这里处理，不漏到命令层。已知的差异点：字符串比较的大小写处理、
"关键字为空就不加过滤"、Oracle 里空串与 NULL 等价。

## 判据

本包没有自己的测试文件；它与本地镜像的**同语义**由命令层的对拍用例承担：

```bash
go test ./internal/cli/dict -count=1
```

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 任何 SQL | **必须与本地镜像那份同步改**，否则两个数据源给出不同答案，而调用方看不出来 |
| 内联值的处理 | 注入面；每一处都要过白名单与引号 |
| 方言分支 | 只影响在线路径，但两边的**结果**必须一致 |
