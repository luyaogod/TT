# internal/dict — ERP 数据字典

查 T100 的元数据：表与字段、校验带值、系统分类码、字段画面规格、可复用开窗、系统消息、
参数定义、程序与作业。**两种数据源、一个接口、一份数据族清单。**

## 两种数据源

| 源 | 实现 | 说明 |
|---|---|---|
| **本地镜像** | [./db](./db/README.md) | 本地 SQLite 副本，离线可用、快 |
| **远程直查** | [./live](./live/README.md) | 连客户的 ERP 库现查，数据总是最新的 |

**两者实现同一组查询方法、返回同一批结构**（[./db](./db/README.md) 的 `Source` 接口），
所以命令层不区分本地与远程 —— 由数据源策略决定，命令本身不关心。

数据源的选取顺序（`cli/dict` 的钩子）：

1. `--env` / `--conn <环境名|local>` —— **显式指定即强制**；
2. 配置里的查询数据源（环境名或 `local`）；
3. 都没有 → **在线优先**（只有连环境都没配时才落到本地）。

## 数据族

**`Families` 是唯一的事实来源**：哪些表属于哪一族、谁依赖它、同步顺序 ——
同步清单、数据覆盖状态、各命令帮助里的"本地数据齐不齐"提示全部从它生成。

下表只是它的一个快照（改了 `Families` 就该顺手改这里，否则以 `Families` 为准）。
**「依赖命令」记的是"会读到这一族里至少一张表"的命令，含跨族 JOIN** —— `desc` 会 JOIN
表字典族的字段档、`docp` 会 JOIN 系统分类码族，所以它们同时出现在好几行里。
命令 → 族的方向**不另抄一份**，由 `dbsync.FamilyKeysForCommand` 从这张表反推
（那些 `--help` 提示就是这么来的）。

| 族 | 中文名 | 依赖命令 | 表 |
|---|---|---|---|
| `table` | 表字典 | `r.t` · `desc` · `prog` · `sysp` · `docp` | 表档 / 字段档 / 键值档 / 索引档等 9 张 |
| `check` | 校验带值 | `r.v` | `dzcd_t` 系 5 张 |
| `scc` | 系统分类码 | `scc` · `desc` · `docp` | `gzca_t` 系 4 张 |
| `spec` | 字段画面规格 | `desc` | `dzep_t` |
| `win` | 可复用开窗 | `r.q` | `dzca_t` 系 5 张 |
| `msg` | 系统消息 | `msg` | `gzze_t`、`gzzal_t` |
| `param` | 参数定义 | `sysp` / `docp` | `gzsz_t` 系 3 张 |
| `prog` | 程序与作业 | `prog` · `r.t` | 程序档 / 作业表 / 应用参数组等 4 张 |
| `progtable` | 程序与表格 | `prog` / `r.t` | `gzdg_t` |
| `subprog` | 子程序与元件 | `prog` | `gzde_t`、`gzdel_t` |

**缺族不是"部分可用"**：依赖它的命令会**整体报错** —— 所以状态表里那种情况行数显示为
"无意义"，而不是给一个会让人误以为能用的数。

## 同步范围：查询读到的表，一张都不能漏

**每条查询命令在在线与离线两种环境下都必须可用。** 在线走远程直查（不依赖镜像），
离线走本地镜像（**完全**依赖镜像）——所以这条要求的落点是：**镜像里必须有查询读到的每一张表**。

**判据：查询层读到的每一张表，都必须在 `Families` 里。** 在
[dbsync](./dbsync/README.md) 或 [live](./live/README.md) 里新读一张表，**同一笔改动里**
把它加进它服务的那一族 —— 只加表不挂族，等于加了张 `db sync` 永远拉不下来的表。
两侧读的表也必须**成对**改：`live` 加了、`db` 没加（或反过来），切数据源时那条命令
就会报缺表或少一列。

漏一张的后果**要说准，别夸大成"静默"**。主表缺失会走 `missingTableErr`
（`cli/dict/source.go`，退出码 3、code `TABLE_MISSING`），看得见；但**附表缺失大多被
`IsMissingTable` 吞成"无"**（`cli/dict` 里 `dzed_t`/`dzec_t`、程序族、`desc` 的 SCC 名称
都是这样），于是：

- 命令报「缺表」时，人得去 `db status` 才知道缺的是哪一族；
- 而附表那一路，**"查过了，没有"与"这张表根本没在本地"在输出上长得一模一样** ——
  后续动作却完全相反（前者改条件，后者去 `db sync`）。

今天两边读的是同一套表（`db/*.go` 与 `live/source.go` 各 32 张，集合相等），
这条**由 `dbsync/tablequeries_test.go` 钉着**：它扫两侧 SQL 里的 `FROM`/`JOIN`，
逐张比对清单。

**例外只有一处，且只有这一处**：`gzou_t`。它是"先知道用哪个账号才连得上库"的
**引导表**（`cli/dict/entacct.go`，在任何查询之前读一次）—— 离线不连库、不需要账号解析，
所以它**不该**进镜像；它同时是客户的企业→账号映射，属凭据面。这条例外登记在那条测试里，
连带它的反面判据（哪天没人读它了，测试会报"例外过期"）。
