# internal/dict/dbsync — 把字典同步到本地

把远程 ERP 库里的字典表拉下来，写成本地 SQLite 镜像。命令行的同步动作与服务端设置页里那张
卡片是**同一份实现**。

## 流程

```
连远程库 → 逐表 SELECT → 写入**临时** SQLite → 依据主键定义建唯一索引 → 原子替换目标文件
```

三条边界：

- **中途失败只清理临时库，不动原库** —— 目标是"要么旧的完整、要么新的完整"，没有中间态。
- **替换前把原库备份一份**（`.bak`），出问题能退回去。
- 表清单来自数据族定义那一处（见 [../README.md](../README.md)），不在这里另列一份。

建索引不是可选步骤：本地查询按主键与常用条件过滤，没有索引的镜像在大表上会慢到不可用。

## 判据

```bash
go test ./internal/dict/dbsync -count=1
```

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 同步的表清单 | 与数据族定义同源；改了要同时想"覆盖状态"与帮助提示 |
| 临时库与替换逻辑 | 最坏的结果是**用户的原库被半截数据覆盖** —— 这一处改动要特别小心 |
| 索引策略 | 本地查询的性能，以及索引建失败时的判定 |
