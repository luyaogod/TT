环境与配置 8

坐标与配置。口令永不进输出；没有默认环境，每次都点名。

会话 session 8

会话是一级对象：它持有身份（ref / name / n / epoch）与作业实例。目标一律 --session，多条不带目标会报歧义并列候选。

示意tt session new --env <环境> --ent <企业> --name <名字> [--prog <作业>]建会话（可同时起作业）

要先有 serve。会话地址是 环境#序号，不是“默认那一条”。

输入
tt session new --env <环境> --ent <企业> --name <名字> [--prog <作业>]
human 输出
会话已建立：主机109#1   名字 A   企业 109   作业 bsft001_wf   状态 idle
json 输出（--json）
{"ok":true,"session":{"id":"s7f3","ref":"主机109#1","name":"A","env":"主机109","ent":109,"n":1,"epoch":1,"prog":"bsft001_wf","state":"idle"}}
示意tt session ls列会话

默认过滤掉 state=exit 的；--all 全出。

输入
tt session ls
human 输出
REF          名字  环境       ENT  作业          用途  状态   世代
主机109#1    A     主机109    109  bsft001_wf   -     idle   1
json 输出（--json）
{"ok":true,"sessions":[{"id":"s7f3","ref":"主机109#1","display":"主机109#1","name":"A","env":"主机109","ent":109,"n":1,"epoch":1,"prog":"bsft001_wf","state":"idle"}]}

示意tt session ent <企业编号> --session <ref>改会话的企业编号（仅空闲时可设）

跑起来之后改不了 —— 那会把账号与 schema 换掉。

输入

human 输出
主机109#1 企业 109 → 99   账号 ds → dsdemo
json 输出（--json）
{"ok":true,"ref":"主机109#1","ent":99,"account":"dsdemo"}
示意tt session job --prog <作业> --session <ref>在这条会话里起一个作业

会话本来就空闲才能起；一轮一个作业。

输入
tt session job --prog <作业> --session <ref>
human 输出
主机109#1 起作业 aapt320 → 等到入口停站 @ aapt320:34
json 输出（--json）
{"ok":true,"ref":"主机109#1","prog":"aapt320","state":"stopped","line":34}
示意tt session exec --session <ref> -- "<fgldb 命令>"透传一条 fgldb 命令

等价 tt debug exec；命令原样给 fgldb，tt 不改写。

输入
tt session exec --session <ref> -- "<fgldb 命令>"
human 输出
> break 812
Breakpoint 1 at bsft001_wf:812
json 输出（--json）
{"ok":true,"ref":"主机109#1","commands":["break 812"],"output":"Breakpoint 1 at bsft001_wf:812"}
示意tt session quit --session <ref>结束本轮（会话保留，回空闲）

会话还在，只是这一轮结束 —— 再 job 就能复用宿主、免重新登录。

输入
tt session quit --session <ref>
human 输出
主机109#1 本轮已结束，会话保留（idle）
json 输出（--json）
{"ok":true,"ref":"主机109#1","state":"idle"}
示意tt session rm --session <ref>收掉会话（断连接、清资源）

与 quit 的区别：rm 之后这条会话不存在了。

输入
tt session rm --session <ref>
human 输出
主机109#1 已收掉（连接断开、资源清理）
json 输出（--json）
{"ok":true,"ref":"主机109#1","removed":true}

数据 db 3

只读 SQL 与连通性。查元数据用 tt dict；这里只回答“库通不通 / 这条 SELECT 出什么”。

示意tt db ping --at <环境>[@<企业>]本机直连一次库（可走 SSH 隧道）

验证网络 / VPN / 隧道与账号口令；对端视角用 probe。
