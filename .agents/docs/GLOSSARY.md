# TT 名词表

为避免歧义，TT 开发过程中的重要名词均在此统一定义。

## 连接层

### 环境与企业

以下名词的定义由 ERP 系统的架构决定：

1. 需要一台或多台服务器来部署 T100 ERP 实例和数据库。
2. T100 ERP 实例需要连接一个数据库。
3. T100 ERP 是一个多集团、多组织架构的 ERP，需要通过 schema 做数据隔离。

因此我们定义：

| 中文名 | 英文名 | 含义及用途 |
|---|---|---|
| **环境** | Environment | **一等公民配置项**：SSH（主机/端口/账号/口令/登录区域）+ 一份数据库配置（一个连接/多份账号密码） |
| **企业编号** | Enterprise / ENT | 不同企业不仅用 schema 做隔离，还体现在大部分业务单据底表的第一个主键上。通过固定账户 `ds` 查询数据库指定表格，可以获取该企业编号数据所对应的数据库账号 |

### 数据库查询

对 TT 而言，需要直接查询数据库的工具必须提供 `环境 + 企业编号`，才能锁定使用哪个账号（schema）来进行查询操作。

我们定义：

| 中文名 | 英文名 | 含义及用途 |
|---|---|---|
| **数据库连接** | DB Conn | 按（环境, 企业编号）取一条只读库连接。 |

### SSH 会话

TT 提供的 debug 功能以及程序操作录制功能，都依赖于一个“活的”SSH 连接，因为需要通过 SSH 来操作服务器上的原厂工具。很多工具都需要透过 `TOPENT` 环境变量来寻址，从而找到应当使用哪个账号来进行数据库查询，这和我们的数据库查询功能的需求是相同的。

因此我们定义：

| 中文名 | 英文名 | 含义及用途 |
|---|---|---|
| **会话** | Session | 一个通过环境中存储的配置打开的 SSH 活连接，并且设定了 `TOPENT` |

根据会话在 TT 上的两种用途，我们做如下区分：

| 中文名 | 英文名 | 含义及用途 |
|---|---|---|
| **SSH 会话** | SSH Session | 会话中执行的是一个 PTY 里跑的调试器（`fglrun -d`） |
| **界面会话** | FEP Session | 隔离的 GDC 实例 + 代理 + 作业窗口 |

### 并发消歧

同一环境、同一企业编号下可以存在多条 SSH 会话（两个 Agent 干同一件事时必然如此）。业务上它们**没有区别**，所以这一维没有语义可用：

| 中文名 | 英文名 | 含义及用途 |
|---|---|---|
| **序号** | Sequence | **同一环境下**的第 N 条 SSH 会话，写作 `#2`。**企业编号是会话的属性，不在地址里** |

> GDC 是连接 T100 服务实例的用户客户端，通过 FEP 协议实现前后端通信。我们通过中间代理捕获其协议，并实现录制和重放用户操作等功能。

## 已定局

| # | 结论 | 日期 |
|---|---|---|
| 1 | **「站点」不作为独立名词**。Agent 指认的是**环境名**（唯一句柄） | 2026-10-16 |
| 2 | 并发消歧段的规范名 = **序号**（写作 `#2`） | 2026-10-16 |
| 3 | 跑 `fglrun -d` 那条会话的规范名 = **SSH 会话**（不叫"调试会话"） | 2026-10-16 |
| 4 | 选择器文法 = **`环境/作业#序号`**，兼容 `环境/企业` | 2026-10-16 |
| 5 | 兼容性策略 = **只在多会话时收紧**（单会话时自动落位，行为不变） | 2026-10-16 |

**两条命名纪律**

1. **"会话"单独出现时必须带限定词**：SSH 会话 / 界面会话。
   因为 `tt fep session` 已经占了这个词根，裸用"会话"在文档里必然歧义。
2. **"站点"只用于两个既有含义**：设置页那个分区名（「站点管理」）、T100 设计器自己的站点清单。
   它**不是** Agent 要提供的东西 —— Agent 提供的是**环境名**。

## 界面与字段（2026-10-17 新增）

ERP 界面上"一个框"牵扯**五样东西**，其中三样都叫编号、**同名不同物**，必须分清：

| 中文名 | 英文名 / 出处 | 会不会变 | 能不能用来找框 |
|---|---|---|---|
| **设计期字段编号** | `.4fd`（设计器保存的文件）里的 `fieldId` | **会变**：每次保存全量重排（`engine/SPEC.md:257`；实测 aapp320 56/56、apmt500 353 处） | ❌ **绝对不可**（写入方与地址解析都必须只用 `name`） |
| **表单字段编号** | `.42f`（编译后的表单文件）里的 `fieldId`；运行期原样读走并出现在 AUI 声明里 | **稳定**（同一表单变体内；实测与运行期语料 **509/509 = 100%**） | ✅ 与 `colName` 组成双键 |
| **会话对象编号** | 运行期给界面节点发的临时 id（AUI 里的 `id`） | **会复用**：单调计数器 + LIFO 空闲栈回收 | ⚠️ **只在单步内有效**，发完即弃，不当身份 |

另外两样：

| 中文名 | 英文名 / 出处 | 含义 | 用法 |
|---|---|---|---|
| **字段标识（工号）** | `colName`（`.42f` 与 AUI 都带，如 `b_xmda001`） | 4GL 侧字段标识符 | ✅ **一等寻址键**（Q8：命令面一律默认工号） |
| **表单变体** | Variant | 同一逻辑表单的不同版本（GUI/TUI 等，如 `fglfind` vs `fglfind_tui`、`*_wf`） | 编号**各自独立**，定位必须带它 |

**定位口径（与计划 `tt-genero-formdef-plan.md` 的冻结口径一致）**：

```
定位键 = (表单 + 变体, colName, fieldId)
  colName 命中 且 fieldId 相符 → 唯一命中
  colName 命中 但 fieldId 不符 → 判为"另一张表单" → 拒
  仍多命中                    → 拒（列候选，绝不自己挑）
```
