功能范围

一句话：把 TT 的官方技能与登记的第三方技能，以项目里的 .agents/skills 为枢纽，一次同步到 Claude Code / GitHub Copilot / Cursor 等 agent 目录；设置页用一张「技能 × 目标」矩阵表达期望态， 同步前给出新增/更新/移除的差异。

v1 范围已经拍板：项目级、复制落盘、页内子标签、CLI 对等。 全局范围、链接、技能市场都不在本轮，见下方「不做什么」。

01问题：能装，但只能一个一个装

现有 tt install skills --to|--agent 一次只服务一个目录；装完之后，没有人知道 「每个工具里那份是不是最新」「哪些目录是我自己放的」。升级时靠配置目录里的 .tt-skills.json 记「装到过哪儿」，但它回答不了逐技能、逐目标的状态。

技能数量少（官方 4 个 + 少量第三方），所以不需要一个「技能库管理系统」；缺的是 多目标分发和每个目标的所有权。

02模型：源 → 枢纽 → 目标

源 · 只读
<exe>\skills skills.externals
官方随发版包走；第三方由用户登记。校验与冲突规则复用 internal/skill。
枢纽 · 项目内
.agents/skills
随项目 git 走；多数客户端默认读它。它是矩阵里的一列，不是隐藏动作。
目标 · 各工具
.claude/skills .github/skills .cursor/skills
复制，不建链接。每个目标一份副本，靠同步保持一致。

03v1 做什么

  1. 项目选择：默认取 Web 服务进程的 cwd，记住上次选择；可换任意目录。
  2. 目标检测：.agents / .claude / .github / .cursor 是否存在。
  3. 技能 × 目标矩阵：逐格勾选期望态；列头与行头有全选（三态）。
  4. 五种真实状态：同版 / 旧版 / 未分发 / 未纳管 / 不可用。
  5. 同步：新增 + 更新 + 移除；移除只删清单里 TT 自己写过的条目。
  6. 试算：同一份差异与预计文件数，不写盘、不改清单。
  7. 第三方技能参与矩阵；失联/不合规/撞名的整行禁用并说明。
  8. CLI 对等：tt skills list|deploy|status|remove，与 Web 共用同一份实现。

04v1 不做什么

不做理由
全局（用户目录）范围各工具的全局路径口径不统一，.agents 的项目语义更强；v2 再谈。
symlink / junctionWindows 权限、跨盘、克隆后失效；复制是唯一不会「看着装了其实断了」的方式。
技能市场 / 远程安装技能源固定为发版包 + 用户登记，不做分发网络。
Preset / 标签 / 自定义工具4 个官方技能不需要分组；工具表先写死 4 个，按需加。
改写用户的 AGENTS.md侵入用户文件，收益不明。
接管「未纳管」目录不是 TT 装的不覆盖；要接管请先手动移走。
多机同步 / Git 备份.agents 随项目 git 走就够了，不做第二套同步。

06清单：所有权的唯一凭据

<project>/.agents/.tt-skills.json，随项目入 git，只写相对路径：

{
  "schema": 1,
  "ttVersion": "0.8.3",
  "hub": ".agents/skills",
  "skills": { "tt-dev-tzc": "sha256:9f2c1a4d" },
  "targets": {
    "claude": {
      "dir": ".claude/skills",
      "deployedAt": "2026-11-12T10:24:00+08:00",
      "skills": { "tt-dev-tzc": "sha256:9f2c1a4d" }
    }
  }
}
  • 所有权 = 清单里出现的条目；删除只按这份清单走。
  • 清单缺失 = 没由 TT 分发过；目录里已有内容一律「未纳管」。
  • 哈希：技能目录（排除根 assets/）按「相对路径 + 内容」算 sha256；算之前先在内存里注入 assets 指针，保证「部署后的内容」可复现。
  • 只写项目相对路径，不写用户名、盘符；换机器、换目录不失效。

07验收口径

  • 空项目：勾选 4 个目标 → 试算 → 同步，四棵技能树一次建齐。
  • 旧版：只覆盖清单内条目，不需要 --force；未纳管目录始终不动。
  • 取消勾选：移除只发生在清单内的条目，确认弹层逐条列出。
  • 第三方失联：整行禁用 + 告警，其它技能照常同步。
  • 克隆一个只有 .agents 的项目：枢纽列显示同版，其它目标显示未分发。
  • 重复同步幂等：第二次的差异为 0，清单不抖。

交互与状态

矩阵里的每个格子同时回答两件事：现在是什么，以及这次同步会做什么。

01五种格子状态

状态怎么来的勾选后颜色
同版清单里有，内容哈希 = 当前源无动作绿
旧版清单里有，哈希不一致覆盖更新黄
未分发清单里没有，目录也没有新增蓝
未纳管目录里有，但清单里没有不可选：永不覆盖紫
不可用技能源失联/不合规/撞名整行禁用灰

02目标状态

列头含义勾选时
就绪.agents/skills 已存在写入枢纽
已检测工具的项目目录存在写入该目录
未检测路标不存在先建目录，状态变「将新建」
将新建已勾选但还没同步同步时创建

03七条规则

  1. 勾选 = 期望态，不是删除开关；同步负责把现实补齐。
  2. 新增：目标里没有就复制；同名但未纳管，跳过并告警。
  3. 更新：只限清单内条目，所有权就是覆盖许可，不需要 force。
  4. 移除：清单内条目被取消勾选才删；清单外的一律不动。
  5. 移除要二次确认，弹层逐条列出将删除的目录。
  6. 试算零写入：同一份差异、同样的文件数，不写盘、不改清单。
  7. 矩阵只列 TT 技能源里的技能；项目里用户自己的技能不显示，也永不被删。

CLI / API

Web 与命令行调用同一份 internal/skill；不新增配置节，清单只落在项目里。

01命令面

# 看：技能源、目标检测、矩阵状态
tt skills list   --project D:\我的项目\t100-custom --json

# 同步：默认目标 = 已检测 + .agents；--all = 所有已检测目标
tt skills deploy --project D:\我的项目\t100-custom --all --dry-run
tt skills deploy --project D:\我的项目\t100-custom \
                 --agent claude-code --agent cursor --skill tt-dev-tzc

# 状态：只看差异，退出码 0/1（CI 用）
tt skills status --project D:\我的项目\t100-custom

# 移除：只删清单内条目
tt skills remove --project D:\我的项目\t100-custom --agent copilot --yes

tt install skills 保留为单目标底层（tt update 刷新用它），帮助里指向 tt skills。不新增第二条语义：两者都走同一个 Apply 与清单读写。

02接口

方法路径作用
GET/api/skills/overview?project=<dir>源、目标检测、矩阵、清单版本
POST/api/skills/deploy{project, targets[], skills[], dryRun} → diff + report
POST/api/skills/remove{project, targets[], skills[]} → 删除清单内条目

设计取舍

这些是会影响以后维护的几条，写在这里，免得被当成 bug 重新讨论。

1 · 复制，而不是链接

链接省空间、一处更新，但 Windows 创建符号链接要权限、跨盘不行、仓库克隆后链接失效 —— 三种失败都是「看着装了，其实断了」。复制换来确定性，代价是每个目标一份副本，靠同步更新。

2 · 项目级，不做全局

.agents 随项目走，能被 git 共享，和现有 tt install skills 的 cwd 口径一致。 全局分发要给每个工具各找一个全局路径，口径不统一；UI 上明说「下一版」，避免用户以为忘了做。

3 · 清单是所有权，哈希是判据

没有清单就分不清「TT 装的」和「用户自己放的」，删除和覆盖都会变成猜。 用清单记录所有权，用内容哈希判断同版/旧版；assets 指针让目标与源故意不同，所以不能拿 diff 判。

4 · 未纳管永不覆盖

同名目录但清单里没有，宁可告警也不覆盖。用户可能把一份改过的技能放在那里； 要接管就手动移走再同步，代价是一步操作，换来不会静默丢东西。

5 · 矩阵，而不是向导

向导适合第一次配置，但回答不了「现在哪儿是旧版」。矩阵同时是状态面板和批量操作面； 空状态再给引导，不做两套界面。

6 · 与「设置页不提供安装」的关系

旧注释担心的是「前端再摆一个目标路径输入框，就成了第二条安装入口」。这里不接受任意路径： 目标由同一张 agent 表推导，试算与落盘都调 internal/skill。它是同一个入口的第二个视图， 注释要按这个理由改写，而不是删掉。

7 · 不做市场、预设、备份

TT 的技能只有 4 个官方 + 用户登记的几个，版本跟二进制走，没有「从网上挑技能」的需求； 项目里的 .agents 本身就是可提交、可分发的载体，不需要第二套同步。
