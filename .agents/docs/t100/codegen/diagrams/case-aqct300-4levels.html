案例解剖：aqct300_wf 质量检验记录维护 四层结构（单头 → 单身 → 缺点原因 → 制造批序号）+ 两个平行分支，正好把「层级 = 键的拼接」讲透

FK / 键 单身层 第三层 第四层 生成物
四层，不是四套代码

qcba → qcbd → qcbe → qcbf 四层，生成出来还是同一套 insert_b / update_b / delete_b，区别只在键数组的长度和索引变量。

平行分支靠"组号"分开

qcbb / qcbc / qcbg 与主干同页面不同页签，靠 ls_group（'1','2','3','4','5','99'）在子程序里各自一段。

一表两页签

qcbd_t 被拆成「抽样与结果」和「检验规格」两个页签，各用一个数组，但都是同一行记录的不同字段子集。

附：层级 ↔ 表 ↔ 页签 ↔ 数组 ↔ 组号

真代码：第四层新增时发生的事

① 查重：四层的键全部来自各自的来源（单头记录、上层数组、本层数组）

SELECT COUNT(1) INTO l_count FROM qcbf_t
 WHERE qcbfent = g_enterprise AND qcbfdocno = g_qcba_m.qcbadocno
   AND qcbfseq = g_qcbd_d[g_detail_idx].qcbdseq
   AND qcbf001 = g_qcbd2_d[g_detail_idx2].qcbe001
   AND qcbf002 = g_qcbd3_d[g_detail_idx3].qcbf002
   AND qcbf003 = g_qcbd3_d[g_detail_idx3].qcbf003

② 组键后交给通用子程序，组号 '99' 对应 qcbf_t 那一段

CALL aqct300_insert_b('qcbf_t', gs_keys, "'99'")

和 axmt500_wf 对照：同一套模型，不同深度

对比项axmt500_wf（3 层）aqct300_wf（4 层 + 平行）
层级主档 → 单身 → 子表单头 → 单身 → 缺点原因 → 制造批序号
键最长4 段（ent,docno,seq,seq1）6 段（ent,docno,seq,001,002,003）
索引变量g_detail_idx、g_detail_idx2g_detail_idx、idx2、idx3
页组数6 组（'1','2','3','8','11','12'…）6 组（'1','2','3','4','5','99'）
一表两页签无有（qcbd 拆「抽样与结果 / 检验规格」）
CRUD 子程序完全相同：insert_b / update_b / delete_b / key_update_b / key_delete_b + lock_b / b_fill

#问题答案在哪
1为什么第四层的键要 6 段？每层贡献自己的主键：docno / seq / 001 / 002+003，层层串起来才是唯一记录
2为什么平行表不用新索引？它们与主干同深度（都挂 qcbd 或都挂 qcba），共用一个 g_detail_idx
3加一个新页签要动生成器吗？不用：r.t 补 FK、表单连线、产生程序，模板会自动多生成一段 ls_group + INSERT
数据取自 aqct300_wf.4gl（本地镜像 2026-03-13 版）与 qcba–qcbg 的 r.t 键值定义；页签名称取自 zh_CN/aqct300_wf.42s。
