# tt dev tzc：安全地改 `.tzc` 代码包

`.tzc` 是 T100 设计器的代码包（一个 zip，装着 FGL 程序、`.tap` 定义、编译好的 `.4gl` 等条目）。
二进制包不能用文本编辑器直接改，`tt dev tzc` 把它渲染成一个带围栏的 4GL 工作区，
让人或 AI 只改该改的那几行，再由工具校验后写回包。

记住一句话：`export` 读包、改工作区、`apply` 写包。

表单包（`.tzs`/`.tzv`）是另一条互不相通的管线，见 `tt-dev-tzs`。拿错入口会被挡住：
`.tzc` 跑 `tzs export` 会以退出码 2 失败。

## 开工前：取修改标记与工号（硬门禁）

`export` 只读，可以先做。**但改围栏正文之前，必须先把下面两个问题问完**——
一次问清，不要边问边改，也不要让用户去记格式。

### 先找「上次备注」

`export` 后，在 `prog.full.4gl` 的 `global.memo` 客制区
（`#add-point:...global.memo_customerization`）里找**最后一条**形如 `#… By …` 的摘要行：

- 上次标记 = 行首 `#` 后面那段（`<单号>#<项次>`，或上次生成的 uuid）
- 上次工号 = `By` 后面那个词

找不到，就是「没有上次备注」。

### 提问（两问；选项只放「不用打字」的答案，输入框留给手动填）

> 卡片里的选项**点一下就提交**，所以绝不能把「可输入」做成选项。
> 选项只放下面这些可以直接选的答案；要手动填就**不要点选项**，直接在输入框写完按下一题。

**问 1｜修改标记**

> 本次修改标识。不输入时二选一：沿用上次 `<上次标记>` / 用新 uuid（16 位十六进制）。
> 也可以直接在输入框填 `<单号>#<项次>`（如 `A12345#01`），填了以填的为准。

选项：
1. `沿用上次 <上次标记>`（只有存在上次备注时才给）
2. `用新 uuid`（没有上次备注时就是唯一默认）

**问 2｜执行人工号**

> 执行人工号。不输入时二选一：沿用上次 `<上次工号>` / 用 `agent`。
> 也可以直接填（如 `12345`）。

选项：
1. `沿用上次 <上次工号>`（只有存在上次工号时才给）
2. `用 agent`（没有上次工号时就是唯一默认）

### 取值规则

1. **标记**三选一：`沿用上次`（默认，有上次时）/ `用新 uuid` / 输入框手填。
   都没给（留空或跳过）→ 有上次就沿用，没有就生成新 uuid。
2. **工号**三选一：`沿用上次`（默认，有上次时）/ `用 agent` / 输入框手填。
   都没给 → 有上次就沿用，没有就写 `agent`。
3. **标记与工号互不绑定**：标记用 uuid 时，工号照样可以手填、沿用上次、或选 `agent`；
   只有工号也没给（且没有上次工号）时才写 `agent`。
4. 提问里要把 `<上次标记>` / `<上次工号>` 换成真实值。
5. **「沿用上次」的标记必须能过工具校验**（`<单号>#<项次>`）。上次是旧格式（例如只有
   `C20261014-XY000605`、没有 `#项次`）时不能直接沿用：按「没有上次备注」处理（用新 uuid），
   并告诉用户「上次的标记缺项次，可补成 `<单号>#<项次>` 后手填」。

- uuid = **不带分隔符的 16 位小写十六进制**（如 `3f9a1c07b2d84e56`），每次新生成。
- **不许自己编**单号、项次、工号；只允许上面这些来源。
- 回答用户时**必须说明本次实际用了哪个标记、哪个工号**（沿用了上次备注也要说明）。
- 这一问一答结束之前：不改围栏正文、不 `apply`。
- `apply` 必须带 `--tag <标记> --operator <工号>`；工具会核对 memo 里有没有对应摘要行，
  缺了直接拒绝（退出码 3）。`--no-tag` 只给合成/测试包，客户包不要加。

## tzc文件基本处理操作

```powershell
tt dev tzc export "D:\pkg\capt110(c).tzc"   # 包 → 工作区 D:\pkg\capt110-ws（-o 可改）
cd /d D:\pkg\capt110-ws                     # 进工作区后所有命令都能省 <dir>

# 只改 prog.full.4gl 里标着 EDITABLE 的围栏正文
tt dev tzc status                           # 改了什么、在第几行、会不会被拒
tt dev tzc verify                           # 不写盘预检
tt dev tzc apply --tag A12345#01 --operator 12345   # 校验通过才写回包（先备份旧包）
```

工作区长这样：`prog.full.4gl`（可编辑的渲染结果）、`manifest.json`（源包身份与 sha256）、
`snapshot/`（逐条目快照）、`.tdev/`（比对基线 `base.full.4gl`、上一版包）、`.git/`（每次 apply 一次提交）。

## 在注释区添加摘要注释并说明修改人

标记与工号已在「开工前」取得；这里只负责把它们写进代码，**全文用同一个标记**。

1. 在 `global.memo` 这个 add-point 内加一行本次修改的标题（摘要），格式：

```
#<单号>#<项次> <作业日> By <工号> <一句说明>
```

例：`#A12345#01 20261028 By 12345 新增客户信用额度校验`

没有上次备注、标记选 uuid 时（工号按取值规则，可以是实际工号，也可以写 `agent`）：

```
#3f9a1c07b2d84e56 20261028 By 12345 新增客户信用额度校验
```

摘要默认加在客制区，除非用户有特别要求：

```
#add-point:填寫註解說明(客製用) name="global.memo_customerization"
...
#A12345#01 20261028 By 12345 新增客户信用额度校验
#end add-point
```

> 如果 `global.memo` 落在锁定区段里，先按「不能做的事」第 5 条走 `unlock`（`--yes` 必须由人确认）。

2. 本次涉及到的代码修改，用**同一标记**成对包裹（开始 `-s`、结束 `-e`）：

```
#A12345#01 -s
...
#A12345#01 -e
```

标记是 uuid 时，块也用同一个 uuid：

```
#3f9a1c07b2d84e56 -s
...
#3f9a1c07b2d84e56 -e
```

## 关于“围栏”

`prog.full.4gl` 不是孤立文件，它是一份从包渲染出来、还要原样写回去的映射。
所以文档用 `{//@tdev:begin point …}` / `{//@tdev:end …}` 这类行把「哪些字节属于哪个定义点」标死：

- 围栏行本身是坐标，改了就整份映射作废，gate1 直接拒。
- 围栏外的字节（文件头尾、区段之间的空行、缩进）必须逐字节不变，所以不要用格式化工具重排整个文件。
- 结构行（`END FUNCTION` / `END DIALOG` / `END REPORT`）逐字节比对，同样不能改。

## 不能做的事

1. 不要改围栏行、结构行、围栏外的任何字节。只改围栏正文。
2. 不要手改 `.tap`、不要绕开工具直接改 zip：写回包的唯一路径是 `apply`。
3. 不要编辑 `.tdev/base.full.4gl`：那是 gate1 的比对基线，改它等于伪造验证。
4. 结构变化走工作区动词：改函数签名用 `tt dev tzc rename`（同步围栏 `fn`、签名行、描述块），
   加新函数用 `tt dev tzc newfn`（带设计器模板，它没有 `--desc`）。
5. 不要硬改只读区段：先 `tt dev tzc unlock`。解锁单向不可逆（解开后规格调整不再自动生成程序代码），
   `--yes` 必须由人确认，AI 不得自主加；锚点区段即使解锁也依然只读。
6. 不要动真实语料或客户包：`export` 只读源包，实验一律用副本或临时目录。
7. 源包在 export 之后被别人动过，就重新 `export`：`apply` 会发现 sha256 不符并拒写（退出码 5）。
8. 如果用户的需求必须要改代码框架，请如实告知用户，询问用户是否需要解开框架，如果用户明确批准，你可以执行命令解开代码框架
9. 不得在拿到修改标记与工号（或用户拒绝后生成的 uuid）之前开始改代码或 `apply`；也不得让 `global.memo` 与修改块使用两个不同的标记 —— 见「开工前」一节。

## 报错怎么读

`verify` / `apply` 拒绝时会打位置，照着改就行（删除类问题给基线文件的行号）：

```
apply 被拒绝（gate1 error=1 warn=0 info=1）：
  [error] gate1.readonly-region  只读 Region 内容被改动（写入被拒）
            位置：prog.full.4gl:4        ← 你编辑的那份文件 + 行号
            该行：   # 我加的字           ← 该行内容
            deny=section-locked          ← 原因：框架未解开，先 unlock
```

退出码：`0` 成功 / `2` 包格式或用法错 / `3` 验证失败 / `4` 写入被拒（权限、缺 `--yes`）/
`5` IO 与环境失败。（`.tzs` 那条线没有 `3`、多一个 `1`。）
加 `--json` 时 stdout 恰好一个 JSON 对象，每条发现带 `file`/`line`/`snippet`。
