# TDict — ERP 数据字典查询

## 这是什么

TDict 带一份**ERP 数据字典与业务元数据**：系统中每张数据表是干什么的、每个字段的中文含义与类型、字段会被怎样校验、下拉选项从哪来、画面字段用什么控件、程序报错编号的文本是什么、某个系统参数是做什么的——用一条命令按**表名或编号**就能查到，不用翻代码、翻画面、问人。

随包的 `erp_data.db` 通常已含大部分字典数据（表字典/校验带值/系统分类码/字段画面规格/可复用开窗/系统消息/参数定义），但**「程序与作业」等数据族不一定已同步**（便携包就没有）。

**查询缺省走在线**：用默认环境（`hosts.activeEnv`）的 ERP 库直查，**数据最新最全、不需要先同步**；本地 `erp_data.db` 是副本（要 `tt dict db sync` 才更新），用于离线或求快。**两者不自动切换**——在线连不上会直接报错，不会偷偷改查本地。

**合并后三个工具共用同一份环境清单**（`config.json` 的 `hosts.sshs`，用 `tt env list` / `tt env use <名称>` 查看与切换）：加一台机器一次，调试、字典查询、源码镜像三处都能用。

- **想用本地副本**：`tt serve` →「设置 → 查询数据源」切成「本地 SQLite」（写入 `config.json` 顶层 `query.source`），或命令加 `--env local`（单次）。切到本地后若某数据族是 `✗`（`tt dict db status` 看），依赖它的命令会**整体**报错——先 `tt dict db sync` 补齐。
- **在线连不上**（网络/VPN/账号）：报错里会提示；修好网络重试，或按上面切到本地。
- ⚠️ 别把"缺数据"当成工具坏了：先看当前数据源是哪个（`--help` 末尾与报错都会说），再决定是切在线、还是 sync。

所有输出默认简体中文。版本与构建信息：`tt version`；每个命令的 `--help` 末尾也会带上版本与本地数据状态。

## 能查什么（速查）

| 想查什么 | 命令 | 输入样子 |
|---|---|---|
| 数据表结构：表说明、字段含义/类型/主键、索引 | `tt dict r.t [表名]` | `dzea_t`、`oobd_t`；找表用 `--kw 应收` |
| 字段校验规则（r.v）：校验 SQL、参数、条件、错误讯息 | `tt dict r.v [识别码]` | `v_ooba002_07`，或 `--kw 料号` 搜索 |
| 系统分类码（SCC）：下拉/选项的"值→说明" | `tt dict scc [分类码]` | `4`，或 `--kw 币别` 搜索 |
| 字段画面规格：控件、下拉来源、格式、必填 | `tt dict desc <表名> [字段]` | `oobd_t oobd002` |
| 可复用开窗（r.q）：开窗选单查什么、回传什么 | `tt dict r.q [开窗码]` | `q_apca001` |
| 系统消息：报错/提示编号的文本与处理建议 | `tt dict msg [编号]` | `std-00006`；没编号按语句搜 `--text 密码`、按类型/状态筛 `--type 1 --status Y` |
| 系统参数说明（系统/企业/据点级） | `tt dict sysp <编号>` | `A-SYS-0040`、`E-CIR-0001` |
| 单据参数说明（单据别 + 适用单据） | `tt dict docp <编号>` | `D-MFG-0076` |
| **程序/作业**：这个程序做什么、被哪些作业使用 | `tt dict prog [程序编号]` | `aapi011`，或 `--kw 对账` 搜索 |

**查「数据是什么」时优先用 TDict而不是去翻 CSV/源码文件**：表/字段/校验/开窗/消息/参数的元数据在源码树里**没有副本**，工具里的说明自带中文翻译与字段语义，快且全。但**「这个程序做什么」「为什么这么改」不在它的范围**（见下面 prog 一节的能力边界表）。

## 命令详解

### `tt dict r.t <表名>` — 数据表字典

**这是什么数据**：系统数据表的登记档案。每张表在系统里做什么（表说明/模块/类型）、有哪些字段（字段名、中文含义、数据类型、长度、主键、必填）、主键/外键、索引。读代码、看 SQL、查界面字段含义时用它。

**示例输入**：表名（支持逗号查多张）：`dzea_t`（表登记档）、`oobd_t`、`dzeb_t`。

**输出长这样**：

```
$ tt dict r.t dzea_t
=== dzea_t ===
表说明: 数据表主档
模块: ADZ    类型: X

字段 (31):
序号  字段名        字段说明       数据类型       长度  主键  必填  备注
--  ---------  ----------  ---------  ---  --  --  --
1   dzeastus   状态码       varchar2   10
2   dzea001    table编号   varchar2   15   PK  Y
...

键值 (1):
键名       类型  键值字段   外键表  外键字段
dzea_pk  主键  dzea001

索引 (1):
索引名      类型  索引字段
dzea_pk  U   dzea001
```

输出里的取值说明：**类型**列见文末「类型码」；主键显示 `PK`；必填 `Y`。`--json` 输出结构化对象，`--csv` 平铺字段明细（含表名列）。

⚠️ **多表同查会把每张表的全部字段都打出来**：`tt dict r.t "glab_t,glaa_t,glad_t,apca_t,apcb_t,oocq_t,ooag_t"` 实测 **689 行**（7 张表字段数 58+104+95+156+134+83+59）。只想确认"这几张表分别是什么"时用 **`--brief`**：

```bash
tt dict r.t --brief "glab_t,glaa_t,glad_t"    # 只要 表名/表说明/模块/类型/字段数,3 行
```

读代码提表名的推荐闭环：`grep 出表名 → tt dict r.t --brief 批量解语义 → 需要时再单表看字段`。

### `tt dict r.v [识别码]` — 字段校验带值 (r.v)

**这是什么数据**：字段校验规则库。系统保存数据前做的各种检查（"该字段必须存在/自动带出/两者都要"）是**可复用的校验模板**：每条校验有一个识别码，含一段校验 SQL（SQL 里用 `<field>`、`arg1~9`、`:TODAY` 等占位符，运行时代入实际字段与参数）、外部参数定义与判断条件。想知道某字段被怎样校验、校验不过显示什么错误讯息，或要给字段绑校验时用。

**示例输入**：识别码（形如 `v_表名_用途`，如 `v_ooba002_07`）；不带参数列出全部（`--kw 料号` 按识别码/说明过滤）。

**输出含什么**：列表=识别码/客制（标准/客制）/说明/型态/错误讯息/备注。详情=单头 + SQL 指令 + 参数 + 判断条件：

- **型态**：1=检查存在 / 2=带值 / 3=检查存在并带值
- **SQL 指令**：校验 SQL 原文，末尾附图例说明占位符含义（`<field>` 回传字段、`arg1~9` 外部参数、`:TODAY` 当前日期、`:DEPT` 等全局变量）
- **参数**：顺序、参数名称（对应 `arg1~9`）、日期型态（1=年月日 / 2=年月日时分秒 / 3=毫秒 / 其他=字符串）、说明
- **判断条件**：顺序、条件 SQL、条件成立时显示的错误讯息

### `tt dict scc [分类码]` — 系统分类码 (SCC)

**这是什么数据**：系统里各种下拉/选项的"选项字典"——币别、单据类型、料件属性、各种分类，统一按分类码组织：一个分类码 = 一组「值 → 说明」，画面上看到的下拉选项就是它。写代码灌下拉、查某字段可选项、按分类码查说明时用。

**示例输入**：分类码（多为数字，如 `4`、`241`）；不带参数列出全部（`--kw 币别` 按分类码/名称过滤）。

**输出含什么**：列表=分类码/群组/状态（启用/停用）/名称/值数。详情=单头（群组、状态、名称、说明）+ **分类值表**（值、说明、排序、标准/客制）——说明列就是下拉里显示的文字。部分分类码的值还带**扩展数据列**（输出中列为 `gzcb003`~`gzcb015`，仅显示非空）：这些列的用途由各分类码自己定义（如某分类码用扩展列存群组编号区间、另一个存格式），结合该分类码的语境理解。

### `tt dict desc <表名> [字段名]` — 字段画面规格

**这是什么数据**：字段在画面上的"设计规格"：每个字段用什么控件（输入框/下拉/日期…）、下拉取哪个分类码（SCC）、显示格式与宽度、必填与否、默认值、开窗程序、最大/最小值、串查程序等——画面设计器按它生成画面，运行期查询界面也按它给下拉灌选项。要复刻/理解某个画面的字段行为时用。

**示例输入**：`tt dict desc oobd_t`（整表）；`tt dict desc oobd_t oobd002`（单字段完整规格）。

**输出含什么**（语义说明）：

| 输出项 | 含义 |
|---|---|
| 控件 | 字段在画面的控件类型：03=ComboBox（下拉）、05=Edit（输入）、09=RadioGroup、01=ButtonEdit（带开窗按钮）、04=DateEdit、11=SpinEdit、12=TextEdit 等 |
| SCC码 | 下拉/单选控件的选项来源=哪个系统分类码（用 `tt dict scc <码>` 查可选项） |
| 必填 | Y/N |
| 显示宽度 | 控件宽度（"整数,小数"） |
| 格式 | 显示格式 |
| 默认值 / 最大/最小值 | 默认值与取值范围（含比较符号） |
| 编辑开窗 / 查询开窗 | 字段上点按钮弹出的程序 |
| 校验带值 | 该字段绑定的校验识别码（用 `tt dict r.v <码>` 查校验内容） |
| 串查 | 串查/参考程序 |
| 大小写 | U/L |
| 客制识别 | 标准/客制 |

### `tt dict r.q [开窗码]` — 可复用开窗 (r.q)

**这是什么数据**：可复用开窗——代码里 `CALL q_xxx()` 弹出的"查寻选单"定义：每条开窗 = 一段带占位符的 SQL（选取字段/表/条件用 `<field>/<table>/<wc>` 标记）+ 外部参数（对应 `arg1~9`）+ 显现列与回传设置。读代码遇到开窗调用、想知道它查什么表、回传哪些值时用。

**示例输入**：开窗码（`q_` 开头，如 `q_apca001`）；不带参数列出全部（`--kw 料号` 过滤）。

**输出含什么**：单头（状态、SQL 指令原文+占位符图例、每页笔数、HardCode（Y=跳过自动产生）、行业别、说明）+ 参数（顺序/名称/日期型态，同 rv 译码）+ 显现设定（显现顺序、字段、显示控件、是否回传——回传 `Y` 的字段按显现顺序构成调用方收到的 `return1~9`）。

### `tt dict msg [编号]` — 系统消息

**这是什么数据**：系统所有提示/报错消息的记录。程序报错、日志里出现的编号（如 `std-00006`）都可以查到它的完整文本、建议处理方式与给维护人员的技术细节——看到报错编号先查它，能直接拿到"怎么处理"。

**示例输入**：查询条件就是作业 `azzi920` 查询画面的那几栏，**同时成立**：

| 条件 | 怎么给 | 匹配方式 |
|---|---|---|
| 编号（gzze001） | 位置参数，逗号分隔可给多个：`std-00006`、`"std-00006,azz-00041"` | **默认精确**；写了 `*` 才是通配（`azz-*` 列该模块全部消息、`*-00006` 找同流水号） |
| 语句（gzze003） | `--text <关键字>` | 默认子串（`--text 密码`）；同样支持 `*` |
| 类型（gzze007） | `--type 0\|1\|2` | 精确，SCC 106：0=警告 1=错误 2=资讯 |
| 状态（gzzestus） | `--status Y\|N` | 精确：Y=启用 N=停用 |
| 建议作业（gzze005） | `--prog <作业编号>` | 精确；**反查"哪些消息建议跑这个作业"**，如 `--prog axmt500` |
| 语言（gzze002） | `--lang <语言别>`，缺省 `zh_CN` | 精确；**进 WHERE 当条件**，不是事后过滤（唯一例外：零结果时补查一次"这组条件在哪些语言下有行"，好把可用语言告诉你） |

- `--type` / `--status` / `--prog` 都可以**逗号分隔给多个**（同一栏内是 OR）；**不同栏之间是 AND**。
- 至少给一个筛行条件（编号 / `--text` / `--type` / `--status` / `--prog`），**只给 `--lang` 不算**——语言决定看哪个语言的份，不是筛子。
- **一律写码、不写中文**（`--type 1` 而不是 `--type 错误`）：家族里其它命令都用码（`tt dict scc 4`、`--lang zh_TW`），两种写法并存只会让人分不清该写哪个。填错了报错里自带对照表：`未知的信息类型 '3'(gzze007);可用值: 0=警告 1=错误 2=资讯`。
- 负整数编号（SQLCODE）需写成 `tt dict msg -- -263`——注意 `--` 之后的都算参数，所以 `--env` 要写在 `--` 前面。

**输出长这样**（命中一条）：跟以前一样打详情块

```
=== std-00006 (zh_CN) ===
类型:     错误 (1)
状态:     启用
文本:     输入的资料已存在
建议处理: 请重新审核您所需要输入的资料
```

**命中多条时打列表**（搜索可能命中几十上百条，如 `--text 密码` 65 条，一条一块详情没法看）：

```
编号         类型  状态  信息语句
---------  --  --  ------------------------
azz-00110  错误  启用  密码错误
azz-00112  错误  启用  密码过期

共 2 条;某条的完整内容(建议处理/建议作业/技术细节)用 tt dict msg <编号> 查
```

要看某条的完整内容，再拿编号精确查一次；`--full` 让多条也逐条打详情，`--limit` 控制列表行数（缺省 20，`0` = 全部；`--json`/`--csv` 是导出，不受 `--limit` 约束）。

输出含：**文本**（报错原文）、**建议处理**、**建议作业**（可执行哪个作业处理，附作业名称）、**技术细节**（给程式人员的详细讯息）、**类型**（0=警告 / 1=错误 / 2=资讯）、**状态**（启用/停用）。消息按 (编号, 语言) 各一条，源系统是精确匹配、无自动回退；该编号没有指定语言的行时会列出可用语言（**编号栏刻意做成精确匹配**，就是为了 `-263` 这种 SQLCODE 不会把 `-26300`~`-26312` 一起捞回来——这是与 azzi920 画面唯一的行为差异，画面里编号栏是子串查询）。

**典型用法**：

```bash
tt dict msg std-00006                  # 有编号：查它怎么处理
tt dict msg --text 密码                  # 没编号：按语句子串找编号
tt dict msg "azz-*" --text 密码          # 两个条件一起收窄
tt dict msg --type 1 --status Y        # 只看"启用中的错误消息"（多少条、都是什么）
tt dict msg --type 1,2 --text 审核       # 多选类型 + 语句子串
tt dict msg --prog axmt500             # 反查：哪些消息建议跑订单维护作业
tt dict msg "azz-*" --limit 0          # 列某个模块的全部消息
tt dict msg azz-00041 --lang zh_TW     # 该编号只有繁体时
```

零结果时命令会补一次诊断，把"为什么没查到"说出来：编号存在但只有别的语言时列出可用语言；否则按你给的条件给对应的提示（编号要写 `*` 才是模糊、语句换个短词、类型/状态/作业之间是 AND 要拆掉一个）。

### `tt dict sysp <编号>` / `tt dict docp <编号>` — 参数说明

**这是什么数据**：系统参数与单据参数——决定系统行为/单据流程的可配置项。参数有编号、名称与中文说明（说明"这个参数是干什么的、怎么填"），并定义可填的**型态、值域与预设值**。

- `tt dict sysp`：**系统/企业/据点级参数**。编号格式 = 型态码 + 领域 + 4 位流水，如 `A-SYS-0040`（A=系统级）、`E-CIR-0001`（E=企业级）、`S-BAS-0028`（S=据点级）
- `tt dict docp`：**单据别参数**（编号 `D-` 开头，如 `D-MFG-0076`），并附它适用哪些单据性质（模块 + 单据性质清单）

**输出长这样**：

```
=== A-SYS-0040 (zh_CN) ===
名称:     系统是否允许LIB相关资源被签出
说明:     系统是否允许LIB相关资源被签出
群:       gzsa_t  系统级参数(系统全域参数)
型态:     Y/N (1)
领域:     SYS
预设值:   N
异常处理: 改抓设定时的预设值 (1)
状态:     启用
```

输出含：名称/说明（多语言）、参数群与级别、**型态**（1=Y/N 2=整数选项 3=范围设定 4=字符或SCC 5=日期）、领域、预设值、值域、SCC 选项、校核/开窗引用、取参异常处理、状态与长备注。`tt dict docp` 额外输出**单据性质绑定**表（该参数作用在哪些单据性质上）。

> 注：这里查的是参数的"定义与说明"；每个环境下参数**实际设的值**不在本命令范围（实际值在各环境的参数值维护画面/作业里看）。

### `tt dict prog [程序编号]` — 程序与作业

**这是什么数据**：程序与作业的登记（来源作业：azzi900 程式基本資料設定作業 / azzi910 作業基本資料維護）。给一个程序编号，得到它的**中文作业名、程序类别、归属模块、是否客制、引用主程序、系统运行指令**，以及**哪些作业用了这个程序**——作业通过 `gzzz_t.gzzz002` 挂到程序上，**一个程序可被多个作业使用**（共用维护程序可达数百个作业）；作业的显示名称取它所挂程序的名称（与 azzi910 的取法一致）。

**什么时候用它**：想回答"这个程序是做什么的"——**这是读 .4gl 代码时最先要问的问题**，源码文件名本身给不出答案（要靠读文件头 `#+ Description:`），而这里一条命令就有；也能拿作业编号反查它挂的是哪个程序。

```
$ tt dict prog aapi011
=== aapi011 ===

```

- `tt dict prog --kw 对账` —— **按中文作业名找程序/作业**（从业务词找人）
- 程序名称有简体（`--lang zh_CN`，默认）与繁体（`--lang zh_TW`）两份，**搜索用字要对应**；同一词还可能有异体（`对账`/`对帐`/`對帳`），搜不到就换个写法或换更短的词
- **拿作业编号也能查**：`tt dict prog aooi701` → 自动跟到它挂的程序（该编号不是程序登记,是作业:挂的程序 = aooi301）
- 一个程序被很多作业使用时默认只列前 20 个（`--limit 0` 全部，`--json` 导出）

**编号查不到时它怎么答**（三类登记是**互补**的，实测两两不重叠）：

| 编号长什么样 | 登记在哪 | `tt dict prog <编号>` 给什么 |
|---|---|---|
| 作业主程序 `aapi011`、`azzq902` | `gzza_t` + `gzzal_t`（名称） | 程序名称/类别/模块/客制/运行指令 + 哪些作业用它 + 用哪些表 |
| **子程序/元件/库** `aapq110_01`、`s_apcp300`、`cl_abi` | **`gzde_t` + `gzdel_t`（说明）**，参考作业 azzi901 | **说明（中文名）、规格类别、归属模块、客制、行业别** + 用哪些表；`_01` 形态还会给出它的主程序 |
| 开窗 `q_adzi052` | `dzca_t` + `dzcal_t` | 不是程序登记，用 `tt dict r.q <开窗码>` 查 |

- 规格类别取值（SCC 91）：`B`=应用元件 / `S`=子程序 / `G`=报表元件-GR类 / `X`=报表元件-XG,FR类 / `K`=报表组件-XR类 / `W`=WebService元件 / `M`=主程序
- 实测规模：`gzde_t` 4,036 个（子程序 1,316 / 应用元件 1,491 / 报表元件 1,130 / 组件 95 / WebService 4）、`gzza_t` 4,147 个主程序，**交集 0**
- 搜索同类编号：`tt dict prog --sub --kw <业务词>`（在子程序/元件里搜，如 `--sub --kw ABI`）；主程序搜索仍是不带 `--sub` 的 `--kw`

**它答不出的**：**这个程序调哪些开窗/用哪些校验**（工具没有这层聚合，要自己 `grep` 出编号再 `tt dict r.q` / `tt dict r.v` 解码）；**动态 SQL**（`CURSOR FROM 变量`）拼出来的表名也不在用表索引里。

### 程序 ↔ 表格（`tt dict prog` 的用表段 / `tt dict r.t <表名> --who`）

数据来自 **`gzdg_t` 程序与应用表格功能分析表**（由 T100 自己维护，参考作业 azzq902「程式編號對應表格查詢」）：主键 = 程序编号 + 表格编号 + 功能类别（SCC 212：`S`=SELECT 查询 / `I`=INSERT 新增 / `U`=UPDATE 修改 / `D`=DELETE 删除）。**两个方向都能查**：

```bash
tt dict prog aapi011              # → 使用的表格 (11):glab_t 是 S/I/U/D,其余多为 S
tt dict r.t glab_t --who          # → 使用它的程序 (376):aapi011 S/I/U/D、aapi201…(改表前的影响分析)
tt dict r.t glab_t --who --limit 0   # 全部(--limit 默认 20)
```

**它比 grep 更准，也要知道它的边界**：

- 比 grep 准：`grep` 会把**被注释掉的 SQL**、**字符串里的表名**(`"dzeb001 IN ('apca_t')"`)、**`LIKE 表名.字段` 的变量声明**都算进来，还会混进 `type_t`；`gzdg_t` 只登记**真实 SQL 访问**并带操作类别。实测 `aapi011` grep 出 16 个候选、其中 5 个是上面那三类噪音。
- 覆盖面比想象中广：**不只作业主程序**——`cl_abi`(库) 22 条、`s_apcp300`(元件) 8 条、`q_adzi052`(开窗) 9 条都在里面。所以 `tt dict prog <库名/元件名/开窗码>` 即使"不是程序登记"，也会给出它的用表清单。
- **边界**：动态 SQL（`CURSOR FROM 变量`）与**子程序**（`aapq110_01` 这类，0 条）不在索引里；这些仍要 `grep` 兜底（见 erp-read 的第 4 步）。

## 数据维护（本地数据怎么更新）

**先确认查询读的是哪边**：缺省是**在线**——直接用默认环境（`hosts.activeEnv`）的 ERP 库直查，数据最新最全，**不需要先同步**；只有查本地副本时才看 `tt dict db status`。两者**不自动切换**（在线连不上会直接报错，不会偷偷改查本地）。

```bash
tt dict db status                    # 本地副本各数据族的覆盖情况(在线时仅供参考)
tt dict db sync                      # 刷新本地副本(全量约 86 万行、2 分钟级;--env 指定从哪个环境刷)
```

**切换数据源**（在线 ⇄ 本地，三选一）：
- 单次覆盖：命令加 `--env local`（本地）或 `--env <环境名>`（该环境在线）——如 `tt dict msg aoo-00120 --env local`
- 前端：`tt serve` →「设置 → 查询数据源」下拉切换（写入 `config.json` 顶层 `query.source`）
- 直接改配置：`{"query": {"source": "local"}}` 或 `{"source": "正式区"}`

**仍然要 db sync 的场景**：想离线用本地副本（切到「本地」后）；本地副本太旧（新表/新消息编号查不到）；`db status` 显示某族 ✗（本地副本缺这一族，用它之前先 sync，或者切回在线）。

## 全局参数

| 参数 | 说明 |
|---|---|
| `--format <json\|csv\|table>` | 输出形态，**默认 json**（带环境信息的信封） |
| `--json` | `--format json` 的语法糖（也是默认） |
| `--csv` | `--format csv` 的语法糖（`# ` 环境头 + 裸 CSV） |
| `--lang <语言>` | 说明语言（r.t/rv/scc/desc/rq/msg/sysp/docp/prog，默认 zh_CN） |
| `--kw <关键字>` | 按识别码/名称过滤（列表类命令：r.t/rv/scc/rq/prog） |
| `--text <关键字>` | 按信息语句过滤（仅 msg：gzze003 子串，支持 `*`） |
| `--type` / `--status` / `--prog` | 消息的类型/状态/建议作业三个筛选条件（仅 msg，可逗号多选，见 msg 一节） |
| `--env <环境名>` | 直接查该环境（远程），如 `正式区`、`测试区`（旧名 `--conn` 仍作别名可用） |

### 输出格式与"我这次查的是哪儿"

**默认就是 JSON**，不用加 `--json`。每个查询结果都带一份环境信息，回答"这条数据是从哪来的"：

```jsonc
{
  "ok": true,
  "env": "主机正式区", "zone": "36", "ent": 99,
  "account": "dsdemo", "accountSource": "accounts[0]",
  "target": "172.16.1.109:1521/t35prd", "dialect": "oracle", "route": "client-direct",
  "readonly": true, "totalRows": 65, "returned": 65, "elapsedSeconds": 0.18,
  "notes": [],
  "data": [ { "编号": "azz-00110", … } ]
}
```

**读结果先看 `account` 与 `env`**：同一个编号在不同环境、不同 schema 下是不同的数据，
`data` 为空时尤其要先核对这两个字段——"上错号/上错环境"与"没有这条数据"看起来一模一样。

- **哪个账号是查 `gzou_t` 按企业编号算出来的**（与 `tt debug sql` 同一条规则）。
  环境的 `topent` 没配或不是数字时会退回账号列表首项，并在 `notes` 与 `accountSource` 里标明。
- 人的眼睛要用对齐表格看：`--format table`。
- 要喂给别的工具：`--format csv`，`# ` 开头的是环境头，`grep -v '^# '` 就得到干净 CSV。
- **出错也是 JSON**：`{"ok":false,"code":"TABLE_MISSING","error":…,"hint":…,"exitCode":3}`，
  靠 `code` 分支（`USAGE`/`ENUM_INVALID`/`ENV_UNKNOWN`/`TABLE_MISSING`/`CONNECT_FAILED`/`QUERY_FAILED`）。
- **退出码**：0 成功（含"查无结果"）/ 1 用法错 / 2 数据源错 / 3 缺表。
  缺表从"打印一句提示就退出 0"改成了退出 3 —— 别再把"没查过"读成"查过了，没有"。

> ⚠️ **Windows 下路径写盘符形式**：`D:\dev\erp-src` 或 `D:/dev/erp-src`，**不要写 MSYS 风格 `/d/dev/erp-src`**——部分 Git Bash 环境里 `/d` 会被解析成真实存在的顶层目录而不是 D 盘，`-d /d/.../erp_data.db` 会**静默落到另一个库上**。另外 `which`/`sed`/`timeout` 在 Git Bash 里可能不存在、或命中 Windows 自带程序（`timeout` 会跑到 `TIMEOUT.EXE` 上报 `Invalid syntax`）——示例命令尽量只用 `tt dict` + `grep`/`find`/`wc`。

## ERP 源码镜像（本地代码路径）

字典数据回答"表/字段/消息/参数是什么";要读 **ERP 实际源码**（.4gl）与前端字段描述（.4fd）时,先确认本地源码镜像:

```bash
tt dict mirror path [<环境名>]    # 输出该环境源码镜像目录(第一行即路径;未镜像会提示)
tt dict mirror pull [<环境名>]    # 下载/更新镜像(增量;--full 全量重建)
tt dict mirror dir                # 查看镜像根目录(未设置时先 tt dict mirror dir <目录>)
```

- 镜像按**目录白名单**取(不是按扩展名),目录与服务器同构:`<镜像根>/<环境名>/` 下有各模块 `erp/<模块>/{4gl,4fd,42s/zh_CN}`、`com/{lib,sub,qry,wss,lng}/{4gl,4fd}` 与 `*.inc`。含三类内容:**4gl**(源码)、**4fd**(前端字段描述)、**42s**(编译字符串,**只取 `zh_CN` 语言目录**)。
- **`*/4gl/*` 下的所有文件都会拉** —— 服务器 4gl 树里混放的副产物也跟着进镜像(实测 `erp/azz/4gl/azzi920.4gl.src`、`azzi310_del_str.42r`)。不在镜像内的是:per(界面源)、正常输出位置的编译产物(42m/42r/42f)、42s 的其它语言、备份残留(`*.bak`/`*.bck`,下次 pull 会清掉本地残留)。
- 拿到路径后用本地文件工具读/搜(ls/rg/按行读),**不要 ssh/scp 去服务器**;镜像更新滞后时先 `mirror pull` 再读。
- 读代码的模块/程序命名规范见 **erp-read** 技能;BDL 语言语法问题见下一节。
