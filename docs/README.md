# docs — 跨目录材料与第三方副本

本目录放**不属于某一个目录**的材料。面向某个目录的说明不在这里 —— 在各目录自己的 `README.md`。

| 文件 | 是什么 | 怎么维护 |
|---|---|---|
| `eval-baseline.md` | `.tzs` 工具面的评测**测量记录**：一份 `SKILL.md` 够不够一个没有对话上下文的执行者把活干对 | **只增不改**：每轮在文件末尾追加一节，与上一轮并排放；判据与装置必须可原样重放 |
| `T100设计器-README.md` | 第三方材料的恢复副本（T100 设计器反编译源码树的 README）。`tt dev tzc` 的**不变量依据**（§3.8 的 I1–I15）与设计器行为依据，实现里的 `file:line` 注释指回它 | 自包含，不依赖其它文档；原文已删，这是逐行恢复版 |

> 曾经有一份 `WIKI.md` 在这里，它是唯一的设计文档（12 章）。它已经按目录拆掉：
> 每一节的内容**回代码核实过之后**重写在对应目录的 `README.md` 里，与代码不符的说法按代码为准。
> 旧的集中文档不再保留。

## 文档分工

| 想知道 | 去哪 |
|---|---|
| 装 tt、第一次配置、配置文件在哪 | 根 `README.md` |
| 从源码构建、依赖、打包 | 根 `BUILD.md` |
| **跑测试**：跑什么、分层、开关总表、真环境怎么配、怎么回读结果 | 根 `TEST.md` |
| 整体结构、分层、关系、术语 | 根 `DESIGN_DOC.md` |
| 在仓库里改代码：改哪块先读什么、什么不能碰、做完的定义 | 根 `AGENTS.md` |
| **怎么用**某个命令、有哪些坑 | `skills/<名字>/SKILL.md` |
| **某个目录内部**是什么、契约是什么、怎么验 | 该目录的 `README.md` |

**一条铁律：同一个事实只在一个地方展开，别处只引用。** 外层讲框架与关系，内层讲细节与契约。

## 目录 README 的体例

**详版（承载逻辑的目录，80–200 行）**

| 节 | 写什么 |
|---|---|
| 定位 | 一句话：这个目录是什么、在链条的哪一环 |
| 职责边界 | 做什么 / **不做什么**（以及为什么不属于邻居）—— 边界比职责更需要写 |
| 关系 | 上游（谁调用我）、下游（我依赖谁）、对外契约面 |
| 机制 | 本目录独有的数据结构与流程 |
| 契约与不变量 | 改代码必须知道的规则 |
| 依据 | 实现 ↔ 设计器源码的对照、偏差表（`.tzc` 管线专有） |
| 判据 | 怎么证明没改坏：一条**可重放命令** + 期望结果 |
| 细节去哪 | 指向子目录 README / SKILL / SPEC |

**短版（薄叶子包，≤600 行源码，15–30 行）**：定位、职责边界、与谁发生关系、细节去哪。四节。

**「判据」节里写什么**（四件，按序）：

1. **一条可重放的命令** —— 别人照着敲能跑出同样结果（`go test <pkg> -count=1` 或
   `./tt.exe …`）。命令要带得上它需要的前置（比如"约 48 秒，跑真实语料"）。
2. **期望结果** —— 要么是一条能看见的数（"通过 31，失败 0"），要么逐条列出测试名与它钉住什么。
3. **覆盖了什么** —— 不是把测试名复述一遍，而是说清**这一层负责证明哪件事**。
4. **故意不覆盖什么** —— 这条最常被漏，也最值钱。**没有真的不覆盖就别硬写**；
   一旦写了，要写清是"结构上难测"还是"留给别的层"，别只写"未覆盖"三个字。

第 4 条防两种误读：以为某个共同约定被盯着，其实没有；以及反过来，指责一个本来就该
归别处的东西"没测"。

现在时的例子：`internal/dev/split` 的判据要写清"`Split` 本身不在本包单测里 ——
它要三件套夹具，归 `tt dev tzc selftest` 的端到端用例"；`internal/web` 要写清
"`hDBProbe` 的快乐路径要真服务器，只有 `hConnTest` 因下游是接口而能测全"。
不写这两句的话，读者会以为那一层已经验过了。

**写作规矩**

1. **内容来源是代码与命令，不是别的文档。** 文档会漂移，只能当线索。
2. **每条断言要能被证实**：指得出代码位置，或给得出一条可重放命令。纯形容词不算。
3. **不写历史**：不出现"曾经 / 合并前 / 旧版 / 最初"这类叙述，只写现状。
4. **会漂移的数字只声明一次**（例如规模、数量），别处写"数见 `<命令>`"。
5. **结尾给一条可重放命令**（沿用 `tools/eval/README.md` 与两份 `fgl-fixtures/README.md` 的习惯）。

## 不写 README 的目录

| 目录 | 理由 |
|---|---|
| `web/dist/` | 构建产物；且 `main.go` 的 `//go:embed all:web/dist` 会把它嵌进二进制，前端构建还会清空该目录 |
| `engine/out/` | 引擎的构建产物，本就不入库（`.gitignore` 里忽略）；只有本机构建过才存在 |
| `engine/designer/` | 第三方二进制程序集（28 个 dll），`.gitattributes` 已标为 binary |
| `engine/src/**`、`engine/test/` | 由 `engine/SPEC.md`、`engine/HANDOFF.md`、`engine/BUILD.md` 覆盖 |
| `skills/<名字>/` | `SKILL.md` 就是该目录的说明；且技能目录的目录名必须等于 frontmatter 里的 `name`，不再加别的文件 |
| `ideas/`、`tasks/` | 工作区：`tasks/` 放核实与待办记录，不对外说明 |
