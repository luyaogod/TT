# AGENTS.md — 项目文档规范

本文件管**仓库里的全部人读文档**：住在哪、每一层写什么、什么不许写。动任何 `.md` 之前读它。

代码注释不归它管 —— 非显然的契约与理由该写就写，那是源码的一部分。

## 文档跟着代码走

没有集中文档，也没有文档索引：**文档按目录树层层组织，一份文档住在它所描述的那一层旁边**。

- 每一层只讲**自己的主题**；对下层只按用途、职责与高层行为点名，**再链接下去**读细节。
- 文档类型不放大范围：一份参考可以把自己那一层写穷尽，但不得替下层展开。
- 越靠内层越具体：内层写契约、不变量、判据；外层写地图、关系、结论。
- **一个事实只有一个家**。别处要么不写，要么一行结论 + 指向它家的链接。

读的人从外往里走：

```
根 README.md              装 tt、怎么跑起来 —— 使用者从这里进
└ 根 AGENTS.md            仓库说明与改代码的规矩：项目结构、构建与测试命令
  └ docs/DESIGN.md        一张有序的地图：分层、进程、文件落点、远程连接链
    └ <目录>/README.md     该目录内部的契约与判据
      └ <子目录>/README.md 再往下同理，到叶子包为止
skills/<名字>/SKILL.md    怎么用某个命令面（对外契约，与源码同级重要）
```

## 一层一个家

| 文档 | 它的活 | 不归它 |
|---|---|---|
| 根 `README.md` | 装、配、跑起来 | 内部契约、构建与测试的规矩 |
| 根 `AGENTS.md` | 仓库说明与改代码的规矩：项目结构、构建与测试命令 | 具体目录的设计（→ 该目录 README） |
| `docs/DESIGN.md` | 整体地图：分层、进程、文件落点、远程连接链 | 包内细节（→ 各目录 README） |
| `docs/AGENTS.md`（本文件） | 文档怎么写、住哪、什么不许写 | 产品行为本身 |
| 各目录 `README.md` | 该目录内部的契约：做什么 / **不做什么**、上下游、独有机制、不变量、判据 | 全局规矩、别的目录的细节、测试名复述 |
| `skills/<名字>/SKILL.md` | 怎么用某个命令面；评测中执行者唯一能读的东西 | 内部实现与理由 |
| `engine/SPEC.md` | `.tzs` 格式与契约的完整记录（冻结；引用写 `§N`） | 构建步骤（→ `BUILD.md`） |
| `engine/BUILD.md` | 引擎为什么必须单独构建、怎么构建、进包的是什么 | 格式契约（→ `SPEC.md`） |
| `engine/HANDOFF.md` | 交接：现状、核心结论、下一步 | 格式细节（→ `SPEC.md`） |
| `designer-src/**` | 只读代码地图 —— 见下节的例外 | —— |

**放哪**：怎么用 → `skills/`；目录内部的契约 → 该目录 `README.md`；整体关系 → `docs/DESIGN.md`；
改代码的规矩 → 根 `AGENTS.md`。

## 只写当前状态

**现状是这个仓库文档唯一允许的时态。** 历史住在 git 里 —— 不出现"曾经 / 旧版 / 合并前 /
已废弃"这类叙述，也不写实现状态标注（"已实现""将来会支持"）。

- **每条断言都要能被证实**：给得出 `file:line`，或者一条别人照着敲就能重放、结果相同的命令。
  纯形容词不算 —— 说"安全""稳定"就要给出判据与复现命令。
- **会漂移的数字只声明一次**（动词数、包数、项数……）。别处写"数见 `<命令>`"，不抄第二份。
- 结尾给一条可重放命令，让读者自己看见它是对的。

一条**明示的例外**，要求在文件顶部自报家门：

| 例外 | 规矩 |
|---|---|
| **只读代码地图**（`designer-src/**`） | 反编译源码的定位地图，随源码冻结，不随 `internal/**` 演进 |

## 目录 README 要回答什么

每份目录 README 至少回答：**这是什么、在链条的哪一环**；**做什么 / 不做什么**（边界比职责更值得写）；
**谁调用它、它依赖谁**；**本层独有的机制与改代码必须知道的不变量**；**细节去哪**。

其中两节**必须叫这个名字**，其余标题随本层语义自取（`## 改动影响面` 是常见的一节）：

- **`## 判据`** —— 按序写四件：① 一条**可重放的命令**（带前置，如"约 48 秒，跑真实语料"）；
  ② **期望结果**（看得见的数，或逐条说清哪个测试钉住什么）；③ **这一层负责证明哪件事** ——
  不是把测试名复述一遍；④ **故意不覆盖什么**，写清是"结构上难测"还是"留给别的层"。
  没有真的不覆盖就别硬写第 ④ 条；它防的是"以为某个共同约定被盯着，其实没有"。
- **`## 细节去哪`** —— 指向子目录 README / SKILL / SPEC。

长度：承载逻辑的目录 80–200 行；薄叶子包（≤600 行源码）15–30 行。

## 不许出现的东西

| 症状 | 怎么办 |
|---|---|
| 同一个规矩的第二份 | 搜一句特征短语；留一处，其余改链接 |
| 该由下层说的内容 | 删掉，链接到它家 |
| 推理过程：怎么一步步实现的、试过哪些被否掉的方案、测试怎么走的 | 留结论与契约，删过程 |
| 测试名 / 包名 / 动词清单的手抄版 | 指向权威处（`--help`、manifest、源码） |
| 段落墙：一段话塞了好几条规矩 | 拆开，或把细节降回它自己的家 |
| 加粗通胀：处处加粗 | 只加粗改变行为的那个从句 |

## 怎么验

仓库没有文档 linter：文档的漂移由 `make test`（即 `go test ./...`）里这几条断言拦。

| 断言 | 盯着什么 |
|---|---|
| `TestUsageTextHasNoStaleAdvice` | `tzsUsage` 与总帮助里不许出现已删除的 `call` 网关，也不许把几个勾选位写成 `true` |
| `TestRootHelpAndReadmeHaveNoStaleAdvice` | `tt --help` 与根 `README.md` 不许教已删除的 `call` 网关 |
| `TestEngineDocsCiteRealProbeHashes` | `engine/*.md` 引的 `test/*.cs` sha256 必须与文件实际内容一致 |

后两条是拿文档全文当断言对象的：文档里的示例**就是被抄走的那个**。它们只钉住极少数
可判定的字符串，证明不了文档整体正确。

**判据是回读，不是自述**：说"文档和代码对得上"之前，跑一遍命令、把输出贴出来。
