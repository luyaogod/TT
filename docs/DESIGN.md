# TT 项目结构与设计

TT 是一款用于开发鼎捷数智旗下大型 ERP 系统 T100 的 CLI 工具。

## 背景

T100 ERP 系统内部构建了大量设计器、字典与规格管理 GUI 程序，常规 AI Agent 工具无法直接操作 GUI，因而难以获取足够充分的上下文。

T100 ERP 系统的前后端代码开发依赖鼎捷内部封装的开发工具，代码也被打包为包含规格与元数据的压缩文件（`.tzc`、`.tzs`），AI Agent 无法直接操作。

## TT 的主要工作

- 连接 T100 部署的远程 Linux 环境，获取全局变量及数据库连接。
- 针对使用 `Genero BDL` 语言开发的 T100 GUI 程序（如数据字段、字段规格、校验、开窗、DEBUG 等），将其封装为 CLI。
- 针对使用 `C#` 语言开发的 T100 设计器，将其重写或二次封装为 CLI，以便 Agent 直接读写 `.tzc` 和 `.tzs` 文件。
- 提供一套 SKILLS 来辅助 T100 项目开发。
- 提供一套Drawio组件库和CLI工具来辅助绘制低保真原型图

## 核心功能

- `tt debug`：通过 SSH 远程驱动 `fglrun -d` 调试协议，提供本地 CLI 和 Web 调试画面
- `tt dev tzc`：将 T100 开发框架产生的 `.tzc` 文件渲染成带围栏的 4GL 工作区，可直接编辑并打包回 `.tzc`
- `tt dev tzs`：调度 T100 设计器 C# 引擎，提供直接操作 `.tzs` 前端文件的能力
- `tt dict`：提供 T100 项目上下文的核心工具，包含表、字段、检验、开窗、消息、参数、程序等查询
- `tt drawio`：用内置的 T100 组件库画原型图（`.drawio`），供需求调研后与客户确认方案

> 1. 不实现设计器的私有格式：`.tzc` 的行为依据设计器的公开发行物反推；`.tzs` 更彻底——引擎直接加载**设计器自己的程序集**。
> 2. 严禁任何对远程服务器的**非只读**操作。

## 项目结构

```
TT/
├─ main.go          内嵌前端产物并交给命令层。整个文件只做这一件事
├─ internal/        Go 侧全部能力（命令层、共享能力、五条能力线）
├─ web/             前端
├─ engine/          .tzs 引擎（C#）：自己的构建链、自己的产物目录
│  └─ designer/     设计器程序集（随包分发）
├─ designer-src/    设计器的**反编译源码**：只读参考，不参与任何构建
├─ skills/          六套 AI 技能，同时是对外操作手册
├─ tools/           评测装置与打包辅助脚本
├─ installer/       安装包定义
├─ testdata/        测试夹具
└─ docs/            设计材料与第三方材料副本
```

## 核心进程

```
① tt <命令>             一次性命令
        │
        │ 需要常驻能力时借助下面两类
        ▼
② tt serve               本地 Web 服务：常驻、单例
        │
③ tzs-server.exe        .tzs 引擎守护进程，命名管道 JSON-RPC
        ▼
   设计器的程序集（映射到引擎进程内）
```

## 文件管理

落点只解析一次：全部由**配置文件的位置**派生（`internal/config` 的 `Locations`），调用方不得自行拼接路径。

配置文件的位置（第一个存在的胜出）：

```
① TT_CONFIG 环境变量
② --config <路径>
③ <exe 目录>\.portable 存在   → 便携包：配置留在包内，数据跟着包走
④ %APPDATA%\tt\config.json    → 缺省
```

显式指定的路径即为最终答案：文件不存在时也不回退到默认落点。

**数据目录 = 配置所在目录**，其余落点都跟着它：

```
<数据目录>/
├─ config.json       用户数据（口令、环境、路径）
├─ erp_data.db       本地字典库；TDICT_DB / --db 可覆盖
├─ .tt-serve.log     服务日志
├─ .tt-serve.json    运行中服务的 pid 与地址，--stop 靠它寻址
└─ 缓存：ents/ srccache/ execlog/ debug-bps/ spill/     ← 清单见 config.CacheSubdirs
```

清缓存只涉及上述五个目录，`config.json` 与 `.tt-serve.json` 不在其列。启动清理按年龄（7 天）删除，不整体清空——`spill/` 中可能正存放着上一条查询的完整结果。

**工作区**（`tt dev tzc export` 的产物）落在调用者指定的空目录，布局固定：

```
<工作区>/
├─ prog.full.4gl   唯一编辑文件（带围栏）
├─ manifest.json   人机共读索引
├─ snapshot/       原包的逐字节拷贝，恢复源
├─ .tdev/          基线、Region 表、锁
└─ .git/           版本留痕
```

一切落盘均走原子写（同目录临时文件 → Rename），不先删后建；除锁文件外不包含任何时钟，相同输入产出逐字节相同的工作区。

**包文件**（`.tzc` / `.tzs`）是用户自己的文件，一律原地覆盖：TT 不改位置，覆盖前留一份上一步的副本。

**引擎 exe**：`<tt.exe 目录>\tzs\tzs-server.exe`；`tzs.serverExe` 可覆盖。

如需确认落盘位置：`tt config path`（配置与数据目录）、`tt cache`（各缓存占用）。

## 远程连接

登录 → 环境 → 企业 → 账号 → 库

企业编号决定账号（schema）。

```
配置里的环境
  ├─① SSH 登录
  ├─② 加载 T100 环境变量      → 路径类变量全部由登录区域派生
  ├─③ 企业编号                ← 这条链上唯一的“业务身份”
  ├─④ 查企业目录              企业编号 → 账号名
  └─⑤ 库地址                  来自配置，不由企业编号推导
```
