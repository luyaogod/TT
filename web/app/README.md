# web/app — 单页应用

唯一一套 SPA：调试工作台 + 统一设置页。本目录是它的构建配置与入口。

## 文件逐个说

| 文件 | 管什么 |
|---|---|
| `index.html` | 入口页。含**首屏防闪脚本**（暗色是 class 驱动的，脚本必须在首帧前把 class 定下来） |
| `vite.config.ts` | `base`（`/debug/`）、产出目录（`../dist`）、开发代理（两类接口分别处理） |
| `tsconfig.json` | 把共享件目录也纳入编译范围（它在 app 目录之外） |
| `package.json` | 脚本与依赖 |

## 脚本

| 脚本 | 做什么 |
|---|---|
| `dev` | 开发服务器（热更新） |
| `build` | **先全量类型检查**，再打包 |
| `postbuild` | 打包后还原产物目录里的占位文件（见下） |
| `check:tokens` | 4GL 词法的检查项 |
| `check:outline` | 大纲/折叠的夹具对拍检查项 |
| `check:store` | 状态容器的检查项（在 Node 里跑） |

三个检查项都由[工作区根](../package.json)的 `check:app` 串起来一次跑完。它们**都不是浏览器测试**：
用打包器把目标模块打成一个临时脚本交给 Node 执行，因此被检查的模块**不得在模块顶层访问 DOM**。

## 为什么打包后会有一个"还原占位文件"的步骤

后端用编译期嵌入的方式携带前端产物，而**目录不存在时嵌入会直接构建失败**。
所以产物目录里始终保留一个占位文件。前端打包会**清空产出目录**（包括那个占位文件），
由构建后脚本把它写回去 —— 否则改完当场看不出问题，而**下一次全新克隆会构建失败**。

## 中间产物

三个检查项打包出的临时脚本落在 `scripts/.tmp-*.mjs`：**不入库**，也**不能落在产出目录下**
（打包脚本会先清空产出目录）。

## 判据

```bash
cd web && npm run check:app && npm run build
```
