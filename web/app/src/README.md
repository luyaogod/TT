# web/app/src — 应用源码

单页应用的全部实现，**扁平一层**，没有按类型再分子目录。文件数不多，扁平反而更好找。

## 外壳与布局

左边是「环境 → 会话」两级目录，右边是所选目标的面板（标题行 + Tab 条 + 内容）。
状态栏（`STATUS_BAR_H`）钉在**会话页**底部：它报的是这条会话的调试状态（停站/运行/空闲 +
接管按钮），环境树与设置页没有状态可报，所以不横跨整个壳子。
三块主面板（环境页 / 会话页 / 设置）**常驻挂载、只切换显隐**（`Shell.tsx` 的 `Pane`）——
编辑器、滚动位置、面板状态都不会因为切走再切回而丢。左侧目录可以收起（`tt.sidebarCollapsed`）。

```
左侧目录（可收起）│ 主面板：标题行 + Tab 条 + 内容
                 │ 会话页底部：状态栏（STATUS_BAR_H）
```

左树的会话行：**状态圆点**（灰=空闲 / 蓝=登录中 / 绿=运行中 / 橙=停站 / 红=已退出）+
名字，圆点与文字对齐父目录的文件夹图标那一列；悬停时右侧换成「结束会话」按钮。
状态只从 `GET /api/sessions` 来（绑着的那条用 store 里的实时状态盖一遍），树里不另存一份。

| 目标 | Tab |
|---|---|
| 环境页 | 创建会话 / 接口日志 |
| 会话页 | Debug |
| 设置页 | 站点管理 / 数据字典 / DEBUG / 技能 / 应用设置（`routing.ts` 的 `SETTINGS_SECTIONS`） |

环境页的「接口日志」是**已有画面原样搬进来的**（`WsLogView`）。
「创建会话」是**真动作**：填 ENT + 作业编号 → `POST /api/sessions/new` 建一条空闲会话 →
等它登录完（loading→idle）→ 跳到它的 Debug 页。会话页只有 Debug 一屏
（`DebugWorkbench.tsx`，从旧外壳原样拆出来），区别只是它不再自带左侧会话栏。

**数据边界**：环境读 `GET /api/hosts` 的 `sshs`（真实配置）；**会话树是池的投影**——
`store.sessions` 由 `sessionList`（`GET /api/sessions`）与池事件（`session.added` /
`session.removed`）经 `indexFromList` 派生，**本地不再记"有哪些会话"**：
`tt.sessions.v2` 已作废（启动时清掉），旧的 `pruneSessions` 一并下线。所以 CLI、别的浏览器、
AI 建的会话都会当场出现在树上，服务端没有的条目也不会留在树上。每条会话的**运行时**另存一份
（`store.runtimes[id]`）：`state` / `stop` / `prog` / `module` / `mode`。收到别的会话的事件时
更新的是**它那一份**，单例字段只跟绑定的那条走 —— 这是多实例页面的地基
（`useSessionRuntime(id)` 可直接读）。
面板绑定的那条会话仍是 `sessionId`（`tt.sessionId`），
它由路由写（见 App.tsx 的绑定 effect）：**地址栏说哪条，面板就绑哪条**；池事件**不改绑定**
（绑定只能由人点）。注意路由那条失效判定要等 `sessionsLoaded`（池列过一次）才生效 ——
否则深链接到某条会话时，首帧的空池会把地址栏弹回环境页。

调试视图**只有一条 header**（`DebugHeader.tsx`）：左边是源码页签，最右是三个互相独立的开关 ——
terminal（下方面板）、bug-play（调试面板）、list-tree（大纲，树）。三者可同时激活，所以它们不是
"当前选中哪一个"的互斥高亮，而是"这块面开着没有"的开/关。

右侧那一列里同时放调试面板与大纲，但**不是上下硬分屏**：两者是同一条手风琴里的条目
（`RightPanels` 就是那条手风琴），谁占多少高度由内容与展开状态决定，空间不够时一起收缩、
各自内部滚动。两块都在时"先开的在上、后开的排后面"，用 CSS `order` 表达而不是换 DOM 顺序 ——
换顺序会让手风琴条目**重新挂载**，大纲的折叠集合与监视输入框当场丢。
整列的宽度拖拽（`tt.panelW`）仍是原样。

## 路由：哈希

```
#env/<环境名>/<Tab>             环境页 create / wslogs
#session/<会话 ID>/<Tab>         会话页 debug
#settings/<分区>
```

环境名编码后进片段（设置里允许中文/空格），解析时解回来。认不出来的片段一律当成"没有目标"，
由外壳落到第一个环境的「创建会话」；一个环境都没有就落到设置页（先配环境）。
会话 ID 用白名单（`isSessionID`）：ID 里带空格/`..`/中文的**丢弃**，不静默截断 ——
这个值会被用户粘给别人，猜错了就会打开另一条会话。

**两条硬约束**（都是有原因的）：

- **路由模块不得被状态容器运行时导入**，且模块顶层不得访问 DOM。
- 原因：状态容器的检查项用裸打包器把它打进 Node 里跑（桩 window/document），
  顶层碰 DOM 会在测试启动前就抛错。所以 DOM 访问全部留在函数体内、由 React effect 调用。

**首跑让一次**：`App.tsx` 的 `hashWroteRef` 在片段已经指着某个目标时**一个字节都不写**
（规范化交给第二次），否则深链接会被默认目标覆盖。设置页那条「分区 → 片段」同步让的是同一件事。
往后每换一次目标/Tab 都写片段（`replaceState`，不用 push：否则浏览器后退要一格一格走遍所有 Tab）。
URL 停止不动同样是错的：点 Tab 切目标时地址栏不跟，刷新就落回旧页。

## 渲染期异常：错误边界

前端有一批「把远端文本解析成界面结构」的地方（变量树、大纲、报文渲染）。解析器出一次未捕获
异常，React 会卸载整棵根 —— 用户看到整页白屏，且没有任何可读原因（实测：一个两万层嵌套的
变量值就能做到）。

两道防线：

- **解析器自己设上限**（`fglparse.ts` 的 `MAX_PARSE_DEPTH`）：到顶就按文本展示。这是正解。
- **`ErrorBoundary`**：根上一层（`main.tsx`）＋ 每个视图/右侧栏/下方面板各一层（`App.tsx`）。
  它不替代修 bug，只保证「一处坏掉」不把整个工作台带走，并把报错原文摆在界面上。

新加组件的渲染期解析要问一句：**这个输入有上限吗**？没有上限的递归就是白屏的入场券。

## 状态：一个容器

全部前端状态在一个容器里（连接、会话、面板显隐、数据、主题、路由目标）。字段按用途分组，
不按组件切分。外壳那两项也在里面：环境清单 `envs`（每次窗口回到前台重读 `/api/hosts`）
与会话树 `sessions`（**由池派生**：`GET /api/sessions` + `session.added/removed` 事件，见上文的数据边界）。

**连接**：与后端的实时通道是一条 WebSocket，**必须带接口前缀** —— 共享层也有同名路径，
不带前缀会落到共享层去。事件到达后进状态容器，视图只读容器。

## 接口客户端

一个文件管全部 HTTP 调用，分两类：

| 类 | 前缀 | 说明 |
|---|---|---|
| 调试专属（会话、断点、报文日志、WebSocket） | **带** `/debug/api` | 与共享层的同名路径区分开 |
| 共享端点（环境配置、探测、连接测试、安装、镜像、同步） | **不带** | 统一服务在顶层各提供一份 |

> 调试子系统自己也有一个环境配置的只读副本（供它独立运行时装页面用）；统一服务下
> 环境页读写的**必须**是顶层那个。

## 编辑器

两处用到编辑器：源码主编辑器与报文编辑器。**初始化只有一处**，做四件事：

1. **按语言路由 worker**（JSON 模型必须用真正的 JSON worker，否则协议错）；
2. 强制走本地包，**不走 CDN**；
3. 注册 4GL 语言（高亮定义移植自上游，只发注释/字符串/关键字三类 token）；
4. 定义明暗两套主题。

源码编辑器是**单实例 + Monaco 模型复用**（切文件不重建编辑器）。报文编辑器与它共用同一套主题。

## 4GL 语言工具是纯的

词法、大纲、解析、路径、悬停这几个模块**不依赖编辑器组件**，是纯数据与纯函数 ——
所以它们能在 Node 里被直接加载并检查。这是前端检查项能存在的前提，
也是"改一处要同步另一处"的地方（同一套夹具在 Go 侧还有一份对拍）。

## 主题

**只有"解析后的明暗"是渲染依据**：页面根节点的 class 与编辑器主题都跟它走。
"用户选了什么"只用于设置页的选中态与持久化 —— 跟随系统时，系统主题变化会让明暗变，
但用户的选择没变。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 状态容器的形状 | 全站视图；它同时被 Node 侧的检查项加载，**顶层不能碰 DOM**。容器里删字段/删联合成员（如侧栏 sheet 去掉 `session`）时，`store.test.mjs` 用 `setState` 灌的部分状态不会有编译期保护 —— 靠 `npm run build` 的 `tsc --noEmit` 找调用点 |
| 路由键 | 深链接与设置页分区；键只有一份定义，别在别处再列一遍 |
| 外壳的 Tab 键（`EnvTab` / `SessionTab`） | 路由的解析与生成、环境页/会话页、`routeView` 要一起改；键只有 `routing.ts` 一份定义 |
| 左树的数据形状（`EnvBrief` / `SessionItem`） | `Sidebar` / `EnvView` / `SessionView` / store。`SessionItem` 是 `SessionBrief` 的投影（`indexFromList`）：`id` 是**服务端句柄**；改形状等于改树、绑定、结束会话那一路 |
| 外壳的配色 | `index.css` 的 `.dark .dsh-shell` 一处覆盖；搬进来的旧画面也读同一套语义 token，别在组件里再写死颜色 |
| 往片段里写东西的地方 | 首跑必须让深链接一次（见「路由：哈希」），否则深链接全废且不报错 |
| 接口客户端的前缀 | 打错前缀会让请求落到同名但不同的端点上（表现是"数据不对"而不是报错） |
| 4GL 语言工具 | Go 侧有同一套夹具在对拍，两边要保持一致 |
| 编辑器初始化 | 两处编辑器共用它；在这里加东西要注意"必须在任何编辑器挂载前执行" |
