# web/app/src — 应用源码

单页应用的全部实现，**扁平一层**，没有按类型再分子目录。文件数不多，扁平反而更好找。

## 四个视图

活动栏切换四个视图，它们**常驻挂载、只切换显隐**（不卸载重挂）—— 这样编辑器内容、
滚动位置、面板状态都不会因为切走再切回而丢。

| 视图 | 内容 |
|---|---|
| 调试 | 源码编辑器 + 断点 + 调用栈 + 变量 + 时间线 |
| 接口日志 | 报文日志的检索与查看 |
| 服务测试 | 按报文参数调用接口服务 |
| 设置 | 统一设置页（站点管理 / 数据字典 / DEBUG / 应用设置 四个分区） |

右侧栏另有几个面板（调试 / 大纲 / 会话），同样是显隐切换。

## 路由：哈希

`/debug/#settings/data-dict` 这样的深链接——可以直接落到设置页的某个分区，
而不是把用户丢在调试页让他自己找。分区清单（键 + 显示名）只有一份，左树与深链接校验共用。

**两条硬约束**（都是有原因的）：

- **路由模块不得被状态容器运行时导入**，且模块顶层不得访问 DOM。
- 原因：状态容器的检查项用裸打包器把它打进 Node 里跑（桩 window/document），
  顶层碰 DOM 会在测试启动前就抛错。所以 DOM 访问全部留在函数体内、由 React effect 调用。

## 状态：一个容器

全部前端状态在一个容器里（连接、会话、面板显隐、数据、主题、视图）。字段按用途分组，
不按组件切分。

**连接**：与后端的实时通道是一条 WebSocket，**必须带接口前缀** —— 共享层也有同名路径，
不带前缀会落到共享层去。事件到达后进状态容器，视图只读容器。

## 接口客户端

一个文件管全部 HTTP 调用，分两类：

| 类 | 前缀 | 说明 |
|---|---|---|
| 调试专属（会话、断点、报文日志、WebSocket） | **带** `/debug/api` | 与共享层的同名路径区分开 |
| 共享端点（环境配置、探测、连接测试、安装、镜像、同步） | **不带** | 统一服务在顶层各提供一份 |

> 调试子系统自己也有一个环境配置的只读副本（供它独立运行时装页面用）；统一服务下
> 环境页读写的**必须**是顶层那个。

## 编辑器

两处用到编辑器：源码主编辑器与报文编辑器。**初始化只有一处**，做四件事：

1. **按语言路由 worker**（JSON 模型必须用真正的 JSON worker，否则协议错）；
2. 强制走本地包，**不走 CDN**；
3. 注册 4GL 语言（高亮定义移植自上游，只发注释/字符串/关键字三类 token）；
4. 定义明暗两套主题。

源码编辑器是**单实例 + Monaco 模型复用**（切文件不重建编辑器）。报文编辑器与它共用同一套主题。

## 4GL 语言工具是纯的

词法、大纲、解析、路径、悬停这几个模块**不依赖编辑器组件**，是纯数据与纯函数 ——
所以它们能在 Node 里被直接加载并检查。这是前端检查项能存在的前提，
也是"改一处要同步另一处"的地方（同一套夹具在 Go 侧还有一份对拍）。

## 主题

**只有"解析后的明暗"是渲染依据**：页面根节点的 class 与编辑器主题都跟它走。
"用户选了什么"只用于设置页的选中态与持久化 —— 跟随系统时，系统主题变化会让明暗变，
但用户的选择没变。

## 判据

```bash
cd web && npm run check:app     # 词法 / 大纲 / 状态容器
cd web && npm run build         # 类型检查 + 打包
```

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 状态容器的形状 | 全站视图；它同时被 Node 侧的检查项加载，**顶层不能碰 DOM** |
| 路由键 | 深链接与设置页分区；键只有一份定义，别在别处再列一遍 |
| 接口客户端的前缀 | 打错前缀会让请求落到同名但不同的端点上（表现是"数据不对"而不是报错） |
| 4GL 语言工具 | Go 侧有同一套夹具在对拍，两边要保持一致 |
| 编辑器初始化 | 两处编辑器共用它；在这里加东西要注意"必须在任何编辑器挂载前执行" |
