# web/app/src — 应用源码

单页应用的全部实现，**扁平一层**，没有按类型再分子目录。文件数不多，扁平反而更好找。

## 视图与布局

五个视图**常驻挂载、只切换显隐**（不卸载重挂）—— 这样编辑器内容、滚动位置、
面板状态都不会因为切走再切回而丢。切换它们的是主面板**右边**那条竖排图标栏。

| 视图 | 内容 |
|---|---|
| 调试 | 源码编辑器 + 断点 + 调用栈 + 变量 + 时间线 |
| 接口日志 | 报文日志的检索与查看 |
| 服务测试 | 按报文参数调用接口服务 |
| 录制 | 列某个环境/ENT 下的录制件，起一轮 / 停一轮；点开一份看它的身份（启动路径 / 编号表 / 连接清单） |
| 设置 | 统一设置页（站点管理 / 数据字典 / DEBUG / 应用设置 四个分区） |

```
活动栏（设置 / 会话）│ 会话栏（可拖宽，tt.sessionW）│ 主内容面板 │ 视图图标栏
```

右边那条竖排图标栏只有**四条视图图标**（调试 / 接口日志 / 服务测试 / 录制），设置**不在**其中：
设置页自己占满主区域，那条栏也不渲染（它不是这四个容器之一）。主面板**左边**的活动栏常驻、
只有两个图标：设置（入口）与会话（一个收展开关，不是视图切换）。

**会话栏为什么单独一列**：会话是干活前的那个动作（选环境 / 重启 / 结束），四个视图都要用它，
挂在调试视图的右侧栏里别的视图就够不着；而它必须在 App 层挂一次就一直在 —— 挂在视图里面
会跟着视图卸载重挂，手风琴展开态与 TOPENT 输入当场丢。设置页不显示它（环境就在设置页里管，
一列列环境与会话的面板在那里只是重复）。

调试视图**只有一条 header**（`DebugHeader.tsx`）：左边是源码页签，最右是三个互相独立的开关 ——
terminal（下方面板）、bug-play（调试面板）、list-tree（大纲，树）。三者可同时激活，所以它们不是
"当前选中哪一个"的互斥高亮，而是"这块面开着没有"的开/关。原来那套「收起下方面板 / 收起右方面板」
两个按钮已经取消：terminal 就是前者，bug-play 与 list-tree 合起来就是后者。

右侧那一列里同时放调试面板与大纲：只开一块时它占满整列，**两块都开时上下分屏**，中间一条可拖的
分割线（占比 `tt.rightSplit`）。谁在上由 `rightTop` 决定，规则是"后开的在下面"（两个 toggle action
里定的）。顺序用 CSS `order` 表达而不是按顺序渲染两个分支 —— 换 DOM 顺序会让面板重新挂载，
手风琴展开态与监视输入框当场丢。整列的宽度拖拽（`tt.panelW`）仍是原样。

## 路由：哈希

`/debug/#settings/data-dict` 这样的深链接——可以直接落到设置页的某个分区，
而不是把用户丢在调试页让他自己找。分区清单（键 + 显示名）只有一份，左树与深链接校验共用。

**两条硬约束**（都是有原因的）：

- **路由模块不得被状态容器运行时导入**，且模块顶层不得访问 DOM。
- 原因：状态容器的检查项用裸打包器把它打进 Node 里跑（桩 window/document），
  顶层碰 DOM 会在测试启动前就抛错。所以 DOM 访问全部留在函数体内、由 React effect 调用。

**写片段的一方要让首跑一次**：设置页是初始视图，它那条「分区 → 片段」同步比外壳的深链接
解析**先挂载**（React 子 effect 先于父 effect），所以它首跑时若片段已经指着某个视图就一个字
都不写 —— 否则 `#record`、`#wstest`、`#settings/data-dict` 都会被改写成 `#settings/sites`。

**两处都要让这一次**：外壳那条「视图 → 片段」同步（`App.tsx`，用 `viewHash`）首跑时也只
**规范化**片段（非法分区名写成规范的、合法片段一个字节都不改），不按 store 的初始快照去写。
只读不写同样是错的：点图标切视图时 URL 会停在旧视图上，一刷新就落回旧页（实测）。

## 渲染期异常：错误边界

前端有一批「把远端文本解析成界面结构」的地方（变量树、大纲、报文渲染）。解析器出一次未捕获
异常，React 会卸载整棵根 —— 用户看到整页白屏，且没有任何可读原因（实测：一个两万层嵌套的
变量值就能做到）。

两道防线：

- **解析器自己设上限**（`fglparse.ts` 的 `MAX_PARSE_DEPTH`）：到顶就按文本展示。这是正解。
- **`ErrorBoundary`**：根上一层（`main.tsx`）＋ 每个视图/右侧栏/下方面板各一层（`App.tsx`）。
  它不替代修 bug，只保证「一处坏掉」不把整个工作台带走，并把报错原文摆在界面上。

新加组件的渲染期解析要问一句：**这个输入有上限吗**？没有上限的递归就是白屏的入场券。

## 状态：一个容器

全部前端状态在一个容器里（连接、会话、面板显隐、数据、主题、视图）。字段按用途分组，
不按组件切分。

**连接**：与后端的实时通道是一条 WebSocket，**必须带接口前缀** —— 共享层也有同名路径，
不带前缀会落到共享层去。事件到达后进状态容器，视图只读容器。

## 接口客户端

一个文件管全部 HTTP 调用，分两类：

| 类 | 前缀 | 说明 |
|---|---|---|
| 调试专属（会话、断点、报文日志、WebSocket） | **带** `/debug/api` | 与共享层的同名路径区分开 |
| 共享端点（环境配置、探测、连接测试、安装、镜像、同步、录制） | **不带** | 统一服务在顶层各提供一份 |

> 调试子系统自己也有一个环境配置的只读副本（供它独立运行时装页面用）；统一服务下
> 环境页读写的**必须**是顶层那个。

## 编辑器

两处用到编辑器：源码主编辑器与报文编辑器。**初始化只有一处**，做四件事：

1. **按语言路由 worker**（JSON 模型必须用真正的 JSON worker，否则协议错）；
2. 强制走本地包，**不走 CDN**；
3. 注册 4GL 语言（高亮定义移植自上游，只发注释/字符串/关键字三类 token）；
4. 定义明暗两套主题。

源码编辑器是**单实例 + Monaco 模型复用**（切文件不重建编辑器）。报文编辑器与它共用同一套主题。

## 4GL 语言工具是纯的

词法、大纲、解析、路径、悬停这几个模块**不依赖编辑器组件**，是纯数据与纯函数 ——
所以它们能在 Node 里被直接加载并检查。这是前端检查项能存在的前提，
也是"改一处要同步另一处"的地方（同一套夹具在 Go 侧还有一份对拍）。

## 主题

**只有"解析后的明暗"是渲染依据**：页面根节点的 class 与编辑器主题都跟它走。
"用户选了什么"只用于设置页的选中态与持久化 —— 跟随系统时，系统主题变化会让明暗变，
但用户的选择没变。

## 改动影响面

| 改什么 | 会波及 |
|---|---|
| 状态容器的形状 | 全站视图；它同时被 Node 侧的检查项加载，**顶层不能碰 DOM**。容器里删字段/删联合成员（如侧栏 sheet 去掉 `session`）时，`store.test.mjs` 用 `setState` 灌的部分状态不会有编译期保护 —— 靠 `npm run build` 的 `tsc --noEmit` 找调用点 |
| 路由键 | 深链接与设置页分区；键只有一份定义，别在别处再列一遍 |
| 往片段里写东西的地方 | 首跑必须让深链接一次（见「路由：哈希」），否则深链接全废且不报错 |
| 接口客户端的前缀 | 打错前缀会让请求落到同名但不同的端点上（表现是"数据不对"而不是报错） |
| 4GL 语言工具 | Go 侧有同一套夹具在对拍，两边要保持一致 |
| 编辑器初始化 | 两处编辑器共用它；在这里加东西要注意"必须在任何编辑器挂载前执行" |
