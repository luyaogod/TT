# web/shared — 设计系统与共享件

整套 SPA 共用的主题、UI 基元与布局件。**它在应用目录之外**，这一点决定了两条规矩（见下）。

| 文件 | 内容 |
|---|---|
| `tokens.css` | 语义 token + 明暗两套取值 + 圆角策略。**设计规则的唯一出处**（文件顶部注释就是规矩）；暗色是 **class 驱动**，不跟随系统媒体查询 |
| `ui.tsx` | 非依赖第三方库的基元：按钮、徽标、面板、输入、分隔线、表格 |
| `ui-radix.tsx` | 基于 Radix 的封装：下拉、气泡、勾选框、手风琴、日历/日期选择、确认对话框，以及调试状态的色调与文案映射 |
| `settings.tsx` | 设置页的布局件：卡片、设置行、字段、分区标题、信息行 |
| `theme.ts` | 外观主题：暗 / 亮 / 跟随系统；解析、持久化、监听系统变化、把结果应用到根节点 |
| `utils.ts` | 类名合并 |

## 两条规矩

**一、类扫描的入口必须显式声明。** Tailwind 的自动扫描以项目根为界，而本目录在应用目录之外 ——
**漏扫的后果是静默的**：只在共享组件里出现的类不会进产物，构建照样成功，界面却缺样式。
所以应用的样式入口里有一行显式声明本目录作为扫描源。

**二、引入了 token 就等于接管了明暗。** 那份 token 会让"暗色"变体跟着根节点的 class 走，
而不是跟着系统 —— 于是**引入方必须同时具备首屏防闪脚本与启动时的主题应用**，
否则界面会永久停在亮色，而且没有任何报错。

## 样式规矩（出自 `tokens.css` 顶部）

- 组件一律用**语义工具类**，**禁止写死具体色板** —— 亮暗两套取值集中在 token 里维护。
- 布局密度对齐经典编辑器界面：面板紧贴、以 1px 分割线相隔。
- **默认零圆角**，圆角只允许出现在少数几处（按钮、工具图标、活动栏图标、主内容面板），
  一律 6px。别处不要再引入圆角。

## 判据

本目录没有单独测试；它的正确性由使用方承担：

```bash
cd web && npm run check:app     # 含词法检查（会加载共享层能加载的部分）
cd web && npm run build         # 类型检查会覆盖本目录（tsconfig 已纳入）
```
