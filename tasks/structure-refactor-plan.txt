【一】本次执行：删掉 `tt dev install`
================================================================================

为什么删而不是合并成一份实现：
  · 它只是合并期留下的兼容别名（internal/cli/dev/run.go 自己写着"也可用统一的 tt install"）。
  · **它无法转发给 tt install** —— Go 的导入环不允许：internal/cli → internal/cli/dev →

    所以"两份实现合成一份"只有两条路：新开底层包让两边共用，或删掉其中一份。删掉更干净。
  · 删掉之后，internal/cli/install.go:6-7 那句"合并后只有这一份"**才第一次成为事实**

【二】已否决：`internal/debug` 拆 4 个子包
================================================================================

原设想：把 sql（连库 / 只读 SQL / 企业快照）、srccache（源码镜像）、wslog（接口日志）、
bps（断点存档）四组各挪一个包。核实后否掉，两条理由：

1) **切不开一次依赖反转。**
   sql 与 srccache 两组要用主包的 *Config 与 *Manager，并且**直接读写 Manager 的私有字段**
   （cfg / ents / srcMu / src），dbsql.go 与 srcmirror.go 还有挂在 *Manager 上的方法
   （dbsql.go:70 entAccount、:118 RunReadonlyQuery；srcmirror.go:161/170/179/220）。
   子包引用主包就是 debug → debug/sql → debug 的导入环，编不过。
   要走通必须先提 Config+Manager 到 internal/debug/core/，再把 Manager 上那 6 个方法改成
   自由函数或在新包定义接口，另有 4 个测试文件要跟着动。

2) **收益只剩"导航与测试定位"，买不到"公共依赖归位"。**
   （这一条是核实过程中被推翻的原假设，值得留档）
   · 取 ENT 与账号：**早就是公共依赖、且已经抽出来了** —— internal/entdir（155 行，
     在 internal/ 根下）。它只放"与传输无关"的那一半（映射表、快照格式、环境指纹、新鲜期），
     两条路径各自实现"怎么连上去"：debug 走服务器侧 internal/debug/db.go:200，
     dict 走客户端直连 internal/cli/dict/entacct.go:101。这是有意分工，见 entdir 包注释。
   · 会话管理（Manager/Session）：只有调试线用；internal/cli/debug 是 HTTP 客户端，不直接碰它。
   · 数据库执行：服务器侧那条**只有调试线用**（已核实 internal/cli/dict/dbops.go 只借
     internal/host 做 SSH 发现，查询走客户端直连，不跑服务器侧 sqlplus）；探测工具路径的
     共享件在 internal/host/dbprobe.go。
   · 且 session.go 那 3034 行（全仓最大单文件）无论怎么切都不动，主包只从 8231 降到 5223。

结论：为一处只买"好找、好测"的改动付一次依赖反转，不划算。
**若将来 debug 需要被第三条线复用，再重估这一条。**
