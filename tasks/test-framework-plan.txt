分层的唯一硬约束，是仓库自己已经写下的那句（internal/dev/cli/corpus_test.go:22）：

  一条依赖本机配置的测试会时好时坏，那比不测更糟。

所以判据是：**默认档（`go test ./...` 不带任何环境变量）永不因环境而红**。

【四】框架决策①：默认档怎么扩大 —— 最大一块是"接上已在跑的东西"
================================================================================

**事实**（三条命令都可重放）：

  grep -rn "selftest" --include=*_test.go internal/        # 零命中
  grep -n "type selftestCase" -A 3 internal/dev/cli/selftest.go
      # :21  type selftestCase struct { Name string; Run func(dir string) error }
  grep -n "func selftestCases\|func cmdSelftest" internal/dev/cli/selftest.go
      # :76 selftestCases()  /  :28 cmdSelftest(args []string) int

`cmdSelftest` 自己就是一条测试驱动循环（selftest.go:35-56）：`cases := selftestCases()`，
然后对每一项 `os.MkdirTemp("", "tdev-selftest-")` → `c.Run(dir)` → `os.RemoveAll(dir)`。
这**正是** `t.Run` + `t.TempDir()` 的形状，只差一个 `*testing.T`。

**要做的**：新建 `internal/dev/cli/selftest_test.go`，**只写驱动，不写断言**：

  func TestSelftestCases(t *testing.T) {
      for _, c := range selftestCases() {
          t.Run(c.Name, func(t *testing.T) {
              dir := t.TempDir()
              if err := c.Run(dir); err != nil {
                  t.Fatalf("%s：%v", c.Name, err)
              }
          })
      }
  }

**生产代码一行不动。** 收益是**单一来源**的：`selftestCases()` 是那 31 项的唯一定义处，
任何人给 `tt dev tzc selftest` 加一项，`go test` 自动跟着长，第二份实现的风险是零。

**为什么这是"默认档扩大"而不是"多几条测试"**：这 31 项里有十几项走的是
`cmdExport` / `cmdApply` / `cmdVerify` / `cmdRename` / `cmdNewfn` / `cmdUnlock`
的**完整命令路径**（例如"改正文 → apply → 回读 sha256"、"改 → apply → 再改 → 再 apply"
这类迭代操作）。这批代码约 1200 行，今天在默认档里没有一条断言碰到。

**合成夹具能覆盖到哪、覆盖不到哪**（internal/dev/testutil/fixture.go）：
它能构造的是"任意一个形状正常的包"——8 个区段（含 3 个强制只读锚点区段）、
一个 `function.` 自订定义点、几个裸名插入点、混用行尾。

  · 能覆盖（全称命题，"对任意包 P 成立"）：围栏 render∘parse 可逆性、
    export→apply 的事务性与"只动目标点"、三道关的拒绝码、save(pre) vs save(post) 必须不同。
  · 覆盖不到（分布性质，在真实包的形状分布上才成立）：区段标记与 CDATA 形态的**变体**、
    "这个包本来就报 N 条"的基线性质、长度/编码/Zip64 形态。

**哪些语料用例可以改成合成驱动、哪些必须留真语料** —— 给三条可操作的判据：

  1. 可证伪判据：一条语料断言若形如"对每一个包，属性 P 成立"，且**合成包能构造出违反 P 的
     输入**，它就能替。`TestCorpusExportVerify`（corpus_test.go:135）不满足后半条 ——
     合成包只能覆盖 P 为真的那条路径，**证伪不了**"真实包里有合成包造不出的形状会违反 P"。
  2. f.Code 台账判据（**要先实测，不能在规划里断言结论**）：把 corpus_test.go 的
     `reportString` 收集到的 f.Code 按 code 分组统计一次，列出"哪些 code 只在真实语料里
     出现过"。**只对合成包已能触发的 code**，把语料断言降级为冒烟（`TTZS_CORPUS_LIMIT=N`）。
  3. 成本判据：降级不是删除 —— 改成 `TTZS_CORPUS_LIMIT=3` 的冒烟留在默认档，
     全量仍归 `TDEV_DEEP`。

**明确不做**：不把 `TDEV_DEEP` 那两条（`TestCorpusExportVerify` / `TestCorpusApplySimulation`）
整体降级。它们是上百个真实包的分布回归，合成包在定义上就替不了。

**判据**：
  go test ./internal/dev/cli -run TestSelftestCases -v -count=1
  # 期望：31 个 subtest 全 PASS，0 个 SKIP；命令里不设任何环境变量

**反向判据（必须执行一次）**：临时注掉 selftest.go 里 `stRoundtrip` 的一行 sha256 比对，

**病灶清单**（都已核实）：

  internal/cli/dict     约 20 个包级 var：root.go 的 dbPath / srcConfigPath / queryLimit /
                        srcQueryLimit，source.go 的 dataSrc / srcLocal / srcTarget /
                        srcNotes / srcStarted，各命令的 flag 变量；外加 register.go:14 的
                        `var Group` 这个 cobra 单例
                        其中 dataSrc / srcLocal / srcTarget / srcNotes / srcStarted /
                        dbCfg / mirrorCfg **在测试里零引用** —— 也就是说
                        `openQuerySource` / `closeQuerySource` 这条路径从未被单测跑到
  internal/cli/common   common.go:21-37 的 8 个 var（ConfigPath / JSON / CSV / Format /
                        Verbose / Env / WebFS / Version）+ :87 的 MetaProvider
                        现有测试 spill_test.go:121,231 直接写 common.ConfigPath **不恢复**
  internal/debug        db.go:103 dbProbeCache + :106 dbProbeTTL = 10 分钟（包级缓存）
                        session.go:22 rawDebug = os.Getenv("TDBG_RAW") == "1"（init 时定死）
  进程级                os.Chdir（config/paths_test.go:95，已有 t.Cleanup 还原）；
                        os.Stdout 重定向（两份手写实现，见【七】）
  全仓重置 helper 数    1 —— 只有 spill_test.go:300 的 resetFlags，且只服务一条用例

resetFlags 自己的注释已经把病因写清楚了：

  cobra 的 flag 值挂在命令对象上，而 `Group` 是这个包的**单例**：不重置的话，上一条用例
  里的 `--offset 2` 会留到下一条…真机上一条命令一个进程，所以这不是产品缺陷 ——
  是测试必须自己补上的那一步。

**推荐：测试侧 `t.Cleanup` 快照/恢复，生产代码零改动。**

决定性理由是本文【〇】那条前提：**全仓 0 个外部测试包**。同包测试本来就能直接读写包级
var，所以 `ResetForTest()` 能提供而 `_test.go` 提供不了的能力是 **0**。它唯一的区别是
"能被外部包调用"，而外部包没有这些 var 的语境（`dbProbeCache` 之类是未导出的）。
而引入它要付的代价是**"只有测试用的生产代码"** —— `internal/debug/wstest.go`（156 行，
算进源码行数）已经是这类坏味道的一次教训。

具体形态：

  · 包级普通 var → 快照进局部变量，`t.Cleanup` 还原（连同 cobra flag 一起，复用现有的
    resetFlags(Group)）。
  · MetaProvider 这种"init 已永久赋值"的函数变量（被 internal/cli/dict/root.go:69 的
    init() 赋成 srcMeta，无法撤销）→ **不要试图撤销它，改成保存/还原函数值**：
        old := common.MetaProvider
        t.Cleanup(func() { common.MetaProvider = old })
    这比 ResetForTest 干净：连"init 已经赋过值"这个事实都不需要知道。
  · dbProbeCache 这种跨用例缓存 → **先不做**。`resolveDBRun` 要 `*host.SSHConn`，
    而 `SSHConn.cli` 是私有字段（host/ssh.go:18）—— 今天**没有任何测试能碰到这个缓存**。
    为还没发生的污染写 reset 是给假想的问题加代码。真要写那条测试时，同包测试直接
    `dbProbeMu.Lock(); dbProbeCache = map[...]{}; dbProbeMu.Unlock()` 即可；
    届时 `dbProbeTTL`（包级 const，测试改不了）也要改成 var —— **等那条测试真写的时候再做**。

**配套守卫：一条"快照清单必须齐全"的断言。** 上面这个方案的代价是"漏一个 var 就静默泄漏"，
这条代价**必须用断言堵住，不能靠自觉**。做法（仓库有先例：tzs_verb_test.go 的
`docVerbCountClaims` 就在正则扫文本）：

  扫 internal/cli/dict/*.go（`grep -v _test`）里所有包级 var 的标识符，

  ls web/app/scripts/fgl-fixtures/*.4gl | wc -l             → 61

  两侧 README.md **有意不同**（一份 Go 侧口吻，一份前端侧口吻）

两侧 README 都明写"**两份内容必须逐字节相同**，改一处要同步另一处"，
**而没有任何自动化测试在比对** —— 这是全仓唯一一处"写成书面约定却没进测试"的一致性规则。

`grep -rn fgl-fixtures --include=*_test.go .` 只有 Go 侧读取点

前端侧是 web/app/scripts/fgloutline.fixtures.mjs:19 与 fgltokens.test.mjs:25 各自拼路径。
**两侧各读各的，没人比。**

**方案：在 Go 侧加一条比对断言。**

为什么在 Go 侧：`go test ./...` 是**默认档**，会自动跑；前端侧没有默认档
（`check:app` 是显式命令，web/package.json 里没有 `test` 脚本）。放前端侧等于
"只有人记得跑 check:app 时才生效"，那与今天的口头约定没本质差别。

放哪个文件：`internal/dev/fgl/outline_fixtures_test.go` —— 它已经有一套"从包目录逐级
上溯找 testdata/fgl-fixtures"的逻辑，同一套上溯同时定位 web/app/scripts/fgl-fixtures，
不用另写发现代码。

比对什么：
  1. 集合相等：两侧 .4gl + .expected.json 的 basename 集合必须相同（排序后逐项比对）
  2. 逐字节相等：`bytes.Equal`
  3. **不比对** README.md / README.source.md —— 两份 README 本来就该不同。
     这条要写进测试注释，否则下一个人会"顺手"把它加进去然后删掉。
  4. **缺文件不 skip**。依据 internal/dev/cli/tzs_verb_test.go:369 的原话：
     "这些属于仓库本体，不是语料那样的外部数据 —— 缺了就是仓库坏了"
     （同一规矩的另一处：internal/cli/root_test.go:24）

**判据**：
  go test ./internal/dev/fgl -run TestFixtureCopiesAreIdentical -v -count=1
  # 期望：PASS，不需要任何环境变量
**反向判据**：临时改 web 侧一个 .4gl 的一个字符，上面那条必须红。

**顺带记录一个数字**（只声明一次）：前端脚本注释里写着"用例 61 个：通过 58，
已知偏差 3，不符 0"。这个 61 与上面 `ls | wc -l` 的 61 是**同一件事的两个来源** ——
守卫加上之后，如果脚本注释里的 61 漂了仍不会有人发现。
**可选**：断言"夹具组数 == 61"，逼改夹具的人同时改那句注释（属"会漂移的数字只声明
一次"的机械防线，收益小，列为可选）。

【九】框架决策⑥：怎么让"跳过"不变成"静默全绿"
================================================================================

**先承认 go test 已经给的能力，别重复造**：

  · `t.Skipf` 的**文案**已经完整 —— 例如 dev/tzs/corpus_test.go:152 把两个环境变量名
    与缺省根都打出来了
  · `go test -v` 会打印 `--- SKIP: TestXxx (0.00s)` + 跳过原因
  · **`go test` 不带 -v 时**，一个全跳过的包打印 `ok  tt/internal/dev/tzs  0.5s` ——
    看不出跑了 0 条还是 80 条。**这才是真缺口。**

所以**不新增工具、不新增包装**。做两件事：

### 9.1 一条可重放的分诊命令（给人看）

  go test ./... -count=1 -v 2>&1 | grep -E '^--- (PASS|SKIP)' | sort | uniq -c
  # 期望形如：  381 --- PASS  /  41 --- SKIP

这条命令**不新增一行代码**，只是把今天已有的能力写进 `TEST.md` 的对应节
（今天 AGENTS.md:52 只写了 `go test ./...`，没写怎么**回读**"这次到底验了多少"）。
仓库的规矩是"判据是回读，不是自述"（AGENTS.md:189），所以这条命令本身就是
"全绿"这个说法的判据。

### 9.2 skipLedger —— 让"多一跳"必须是一次可 review 的动作（给闸门）

一条测试，扫仓库里**所有** `*_test.go` 的 `t.Skip` / `t.Skipf` 调用点，与一份
**写在同一个文件里的白名单**比对。多一处、少一处都红。白名单每条带层标记：

  type skipSite struct {
      where string // 文件 + 文案的稳定子串
      layer string // "L3" | "L4" | "L0-环境" | "无对象"
      why   string // "需真语料：TDEV_CORPUS / TTZS_CORPUS；开关 TTZS_DEEP=1"
  }

它买到四件事：

  1. "静默跳过"变成"必须改白名单"，而改白名单是一个会被 review 的 diff
  2. 白名单就是分层归属的唯一来源：L3 条数 = 开 TDEV_DEEP 该多跑多少条；
     L4 条数 = 开 TTZS_E2E 该多跑多少条。"这次到底跳了多少"不再靠数
  3. 顺手断言"L3/L4 的跳过文案里必须出现开关名"（正则扫 why 里出现
     TDEV_DEEP | TTZS_DEEP | TTZS_E2E | TTZS_CORPUS）—— 今天大半已经做到了，
     这条只是把它变成不可回退的：**人看到 skip 就知道怎么打开**
  4. "L0-环境"那几处被点名（无 git / 无用户配置目录 / 无本机旧配置），必须写明
     "这条跳过为什么不算假绿"。这一条逼着人区分"这台机器没有 git"与
     "这台机器没有语料" —— 前者不影响结论，后者影响

**放哪个包**：internal/testkit（它 walk 仓库根，与【七】的 helper 同住；
tzs_verb_test.go 的 liveDocs 已经证明"从包目录上溯读仓库本体"这条路走得通）。

**代价（如实写）**：
  · 每次新增一处 t.Skip 都要改一次白名单 —— 这是**故意的摩擦**，但摩擦多了人会烦
  · 白名单里的位置会随文件变动而漂移。**解法**：只记 `文件 + 文案前 20 字的稳定子串`，
    **不记行号**；行号只在报错时现算。这样改文件不会让白名单失效，
    而改文案会让它红（文案是"这条跳过在说什么"，改文案本就该 review）

**判据**：
  go test ./internal/testkit -run TestSkipLedger -v -count=1
  go test ./... -count=1 -v 2>&1 | grep -E '^--- (PASS|SKIP)' | sort | uniq -c
  # 期望：SKIP 数 == 白名单条数 == 44（本次落地时以实测为准）
**反向判据**：在一个 _test.go 里加一处 t.Skip，TestSkipLedger 必须红。

【十】真环境怎么配（决策 B 的展开）
================================================================================

**现状**：约 11 个环境变量散在各处，没有一个地方能说"我的环境是什么"：

  TTZS_E2E  真引擎测试总开关        TTZS_EXE    引擎 exe 路径
  TTZS_WS   工作区                  TTZS_INSTALL 设计器目录（可省）
  TTZS_PKG  一个真 .tzs 的绝对路径  TTZS_DEEP   .tzs 全语料回归总开关
  TDEV_DEEP .tzc 全语料回归总开关   TTZS_VALIDATE sample|all
  TTZS_CORPUS_LIMIT 只跑前 N 个包    TDEV_CORPUS / TTZS_CORPUS  语料根覆盖

**关键事实：`.gitignore:19` 早就忽略了 `/config.local.json`，但全仓没有任何代码读它**
（`grep -rn "config.local"` 零命中）。仓库当初预留了这个位子，从没建起来。

**方案：`config.local.json` + env 覆盖，解析只有一处。**

  优先级：**env var > config.local.json > 内置缺省**
  与 internal/dev/testutil/corpus.go:34 已立下的"谁先设谁说话"同构。
  **覆盖变量设了但指不到目录时返回空，不回落缺省** —— 沿用 corpus.go 已写的理由：

**现状**（engine/README.md 自己承认）：

  引擎的语料回归驱动的是 8–10 个函数，是**回归网，不是函数面的覆盖网**…
  **函数面覆盖目前是空的**，要补得在 Go 侧补。

`engine/gate-w3-fns.py`（75,888 字节）的诉求是：把 Manifest.cs 声明 `Mutating=true`
的 33 个函数，在**一个长驻 `tzs-server --stdio` 进程**里逐个驱动一遍，四类判决
（CHANGED / NOOP / REFUSED / FAIL）+ 一个必须点名的 SKIP。
它**今天跑不起来**：文件在运行时用 importlib 从同目录加载 `gate-w3.py`，那份不在仓库里。

**结论：能在 Go 侧驱动全部 33 个，且不需要那份脚本。**
理由：它从 gate-w3.py 借的每一个共享位，Go 侧都有对应物，而且**已经在跑**：

  借的                          Go 侧对应物                                    状态
  ----------------------------  --------------------------------------------  --------
  帧分类器 g3.res()             tzs.Call / tzs.CallConn + tzs.Reply           已有
  长驻进程 srv()                internal/dev/tzs/stdio_test.go 的 stdioSession 已有
  roundtrip + rt_parse          corpus_test.go 的 runRoundTrip + parseRt      已有
  rt_ok() 的基线相对判据        requireFixedPoint（注释里就写着 gate-w3 第一版
                                犯过的错："stale 等于基线，不是等于 0"）      已有
  ws_of() 工作区                engineEnv / workspaceOf                        已有
  corpus() 语料                 testutil.CorpusRoot + CorpusFiles              已有
  sha() 摘要                    corpus_test.go 的 sha256full                   已有
  33 个写函数的硬编码名单        **不抄**：tzs.FetchManifest + SpecFn.Writes
                                （manifest.go，"改名前的 Mutating"）—— 问引擎   改问引擎
  契约拒绝码表                  同样问引擎：SpecFn.Errors                       改问引擎
  负向对照（bogus args → 契约
  码 + 零字节改动）             **缺 —— 这是 Go 侧唯一要新写的**                要补

驱动骨架也已经在 Go 里：corpus_test.go 的 `corpusOp` + `corpusPass` 就是
"每包：pristine 基线 → 一个 --stdio 进程做一件事 → 产出跑 RoundTrip"，
今天有 4 个 corpusOp（roundtrip / write / edit / action）。

**形态**：internal/dev/tzs/ 新增一个 corpusOp 家族 + 新开关 `TTZS_FNS=1`。

  每包，在**同一个** stdioSession 里：
    open → 读一遍并把路径快照下来 → validate(baseline) → save(pre)
    → [负向对照：每个写函数分组至少一条 bogus args] → 必须被契约码拒
    → save(mid)            必须与 pre **逐字节相同**
    → [每个适用的写函数，按依赖顺序]（DIRTY 组每步之后重读树）
    → validate(after)      newErrors 必须 0
    → save(post)           必须与 pre **不同**，否则每个写都是静默空操作
    → close
  然后另起一个进程，对 pristine 与 post 各跑一次 RoundTrip，判据用 requireFixedPoint。

四类判决与 gate-w3-fns.py 逐字对齐（那四类是对的）：
  CHANGED = ok:true 且有正向标记
  NOOP    = ok:true 且 noop:true —— **是声明的成功，不是失败**
  REFUSED = ok:false 且 code 在契约里声明
  FAIL    = 其余一切，**包括 E_NOT_IMPLEMENTED 与 E_INTERNAL**
            （"声明了但没实现"与"意外异常"正是这个关卡要暴露的两件事）
  SKIP 必须点名缺哪个前置，裸 skip 不算证据

**"一进程跑完整个序列"这条判据必须保住。** 理由（gate-w3-fns.py 文件头，可核实）：
`ComponentTabIndexService.Register` 不清它的两个列表，所以同一进程里第二次 tab 操作
会接着第一次编号（实测：第二次 clear 编 8..15 而不是 1..8）。
**一个"每次调用一个进程"的装置看不见这个。** Go 侧的 stdioSession 天然满足这条。

**判据**：
  TTZS_FNS=1 TTZS_CORPUS=%TEMP%\ttws TTZS_EXE=<repo>\engine\out\tzs-server.exe \
    go test ./internal/dev/tzs -run TestFnsGate -timeout 30m -v
  # 期望：一行汇总 "33 driven / a CHANGED / b NOOP / c REFUSED / 0 FAIL / 0 unnamed-SKIP"
  # 且不开 TTZS_FNS 时这条完全不出现在 go test ./... 的输出里（不是 SKIP，是不注册）

**两条硬纪律跟着守**（AGENTS.md §2）：① 只在副本上跑（会往源包旁边写临时包）；
② 整轮跑的时候不要重建引擎（`build.sh` 覆盖 out/*.exe 会让 spawn RoundTrip.exe 得到
"The system cannot find the file specified"，表现为几条假红）。

**落地后必须改 `engine/README.md` 那一节**（"函数面覆盖目前是空的"）——
依据 docs/README.md 写作规矩 3"不写历史"，修好之后要改成现状 + 判据命令。
**`engine/gate-w3-fns.py` 保留不删**：它的文件头是"四类判决 + DIRTY_FNS + 基线相对判据"
这三件事的原始论证；只补一句指向 Go 侧实现。
