# 评测提示词（逐字）

一个执行者一份。**只给它这一份提示词** —— 不给仓库路径、不给对话上下文、不给这份文件的其余部分。
把 `<TASK>` 换成 `E1`…`E4`，`<工作区来源>` 那一段照 `setup.py` 实际用的填。

四个执行者可以并行跑（装置互不干扰）。跑完之前**不要**动工具面或文档：那一轮的数字要与同一份
SKILL、同一份 tt.exe 对应。

---

## 提示词正文

你是一个执行者，手上有 Bash 工具。硬约束：

**你只允许读一个文档**：`<仓库>/skills/tt-dev-tzs/SKILL.md`（整份读完）。
不许读本仓库里的任何其它文件 —— 尤其 `docs/WIKI.md`、`README.md`、`engine/**`、`internal/**`、
`skills/` 下别的目录 —— 也不许猜它们写了什么。你只按 SKILL 干活。
（读你要处理的那些包、以及在工作区里写文件，当然都可以。）

环境（都给你绝对路径，照抄就行）：

    可执行文件：`<装置根>/<TASK>/tt.exe`
    环境变量：  `TT_CONFIG=<装置根>/<TASK>/config.json`
    工作区：    已经写在那份 config.json 里了，**不要**再传 `--workspace`

调用形状：

    TT_CONFIG=<装置根>/<TASK>/config.json <装置根>/<TASK>/tt.exe dev tzs <动词> --args '<JSON>' --json

**路径一律写正斜杠**（上面这几行就是）：反斜杠在 Git Bash 下会被吃掉一层，而症状是"配置根本没
被读到 → 工作区未配置"，看起来像环境坏了。2026-09-25 的第三轮里两个执行者都指出**提示词自己
给的是反斜杠前缀** —— 是 SKILL 那条警告救了他们。那是这个文件的错，已改正。

（先 `export TT_CONFIG=…` 一次也行，那样后面只写 exe 的全路径。PATH 上没有 `tt`。）

你要做的事（用户的原话）：

> <本任务的任务句，见下>

做完之后，在你最后一条消息里给三样东西：

1. **你做了什么**：按顺序列出你跑过的命令（可以直接抄你跑的那几行）。
2. **你怎么确认它真的改对了**：你回读了什么、看到了什么。不要只说"成功了"。
3. **说明书的问题**：SKILL 里说得不对、说得不清楚、或者让你多花了几次调用的地方。逐条写，
   能引原句就引原句。这一条比前两条都重要 —— 你踩到的坑就是我要的东西。

如果某一步失败：把错误原样贴出来，说清你怎么理解的、怎么绕过去的。不要反复重试到天荒地老。
不要修改工作区里任何**已经存在**的文件。

## 四个任务句（"用户会说的话"，不含工具术语）

| | 任务句 |
|---|---|
| E1 | 把 `aapt300` 这张表单里名叫 `net108` 的那个字段的「是否可编辑」设为「否」，然后把改完的表单**存成一个新包** `_ai_e1.tzs`（不要覆盖原包）。 |
| E2 | 把 `aapt300` 里名叫 `HBoxT1` 的那个容器「隐藏」起来，然后把改完的表单**存成一个新包** `_ai_e2.tzs`（不要覆盖原包）。 |
| E3 | 给 `aapp320` 这张表单，按数据表 `pmdl_t` 的两列 `pmdlent` 与 `pmdlsite` 各加一个字段，然后把结果**存成一个新包** `_ai_e3.tzs`（不要覆盖原包）。 |
| E4 | 先把 `aapp320` 打开、让它开着；然后再打开一次。如果第二次被拒，按说明书的说法处理。最后回答三个问题：① 第二次为什么会被拒？② 你最后是怎么做的？③ `open` 的参数表里有一个 `force`，它能不能用？ |

**E1 的目标字段换过一次**（2026-09-25，基线 F7）：原先用 `apcb113_s`，而它的「是否可编辑」
**本来就是「否」** —— 那次实际测成了一次"什么都没改"。换成 `net108`：同一个表单、同样是个
`Edit` 控件、当前是「是」。判据（`grade.py`）跟着换成了同一个字段。

**测的是什么**：E1 = 规格侧的 Y/N 勾选位（写 `"true"` 会静默走偏）；E2 = E1 的**对照组**
（`hidden` 是 BOOLEAN，写 `"Y"` 会被值校验拒）；E3 = 最高频的真实工作流（一条命令做完
挑容器 + 建字段 + 校验 + 另存）；E4 = 占用冲突与 `force` 那处文档。

## 跑完之后

1. 四个都结束了再跑判据：`python tools/eval/grade.py --run <装置根>`。
2. 指标（调用次数 / tokens / 耗时）来自**启动执行者的那一侧**，脚本不产出它 —— 把它和判据结果
   一起写进 `docs/eval-baseline.md` 的新一节，并与上一轮**并排**放。
3. 摩擦报告（第 3 条）是这一轮的主要产出：按"代价"排序，逐条给依据，能修的当场修、不能修的记档。
