# `.tzs` 工具面评测装置

三个文件，一个循环：**准备装置 → 派只拿 SKILL 的执行者 → 回读产物**。

| | |
|---|---|
| `setup.py` | 每个任务一份**全新**的工作区副本 + 该任务的 config.json + 一份 tt.exe，并记下逐文件 sha256 基线 |
| `prompts.md` | 交给执行者的提示词**逐字**（含四个任务句） |
| `grade.py` | 回读产物：装置完整性 + 判据回读。**不接受执行者的自述** |

结果（数字 + 判据 + 摩擦报告）记在 [`docs/eval-baseline.md`](../../docs/eval-baseline.md)，
两轮并排。两轮都是 2026-09-25/24 跑的，四个任务各一次。

## 怎么跑

```bash
# ① 装置（四个任务 × 130 MB ≈ 520 MB，robocopy 几秒到一分钟）
python tools/eval/setup.py --src D:\t100_wrok_dir\hengshuo\prd --exe tt.exe

# ② 一个任务一个执行者（只给它 prompts.md 里那一段）
#    跑完之前不要动工具面或文档 —— 那一轮的数字要对得上同一份 SKILL、同一份 tt.exe

# ③ 判据（四个执行者**全部结束之后**再跑；它会 open 那些工作区，与还在跑的执行者会撞会话）
python tools/eval/grade.py --run %TEMP%\ttrun
```

`--tasks E1 E2` 可以只准备一部分；`--run` 换装置根（默认 `%TEMP%\ttrun`）。
`grade.py` 的退出码：**0 = 干净；1 = 判据没达成**（执行者真的没做到）；**2 = 判据都过了，但装置
有问题**（比如 `pristine.txt` 不在 —— 那是"这一轮的数字要人看一眼再信"，不是"活干砸了"）。

## 为什么这么设计（每条都是踩出来的）

- **一个任务一份整副本，不是共用一份。** 工作区是**目录级**的绑定，四个执行者并行时共用一个
  工作区会互相看见对方的包与守护进程。
- **只拷 `mta/` 不够**：加载会弹一个无消息泵的模态框，然后 90 秒超时（`E_FATAL_LOAD_TIMEOUT`）。
- **基线取自每份副本建立时的那一刻，不取自源目录。** 源语料会变（实测：磁盘上已经比 pin 多出
  三个包），而"执行者有没有动过不该动的东西"问的是它拿到手的那一份。
- **比逐文件 sha256，不是只比文件名。** 后者挡不住"改了内容、名字没变"。
- **执行者只读 SKILL。** 真机上它还能读 WIKI/源码，所以这里的失败是**难度的上界**：这里能过，
  真机更宽松。（这也是为什么这一轮的数字不能当"通过率"读，只能当**摩擦**读。）
- **参数写文件、不写命令行**：Windows 的引号与反斜杠会吃掉一层转义（`--args` 里那条坑，
  SKILL §4.2 专门讲过）。判据脚本因此一律走 `--args-file`，而且那个文件落在**任务目录**，
  不落 `ws/` —— 否则它会被清单比对当成"多出来的文件"。

## 已知偏差（读数字之前先读这段）

1. **同一个模型既是文档作者又是被测执行者**：SKILL 里某些说法之所以"够清楚"，可能是因为写它的
   人与读它的模型共享同一套先验。换模型，数字会变。
2. **只有 4 个任务、单次运行**：样本小，不构成统计。用途是**找问题**，不是给通过率。
3. **耗时不可比**：四份副本并行跑，互相争 CPU 与磁盘。
4. **指标（调用数/tokens/耗时）不在这里产出** —— 它来自启动执行者的那一侧（Agent 工具汇报的
   `tool_uses` / `subagent_tokens` / `duration_ms`）。本装置只负责两件事：让四次运行可比、
   把产物判对。
